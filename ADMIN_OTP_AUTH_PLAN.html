Traffic Catcher 이메일 OTP 관리자 인증 기획서

등록된 관리자 이메일로 6자리 인증번호를 발송하고, 인증된 세션에서만 Gemini 시스템 지침을 관리하는 보안 구조

1. 목적

기존 관리자 비밀번호 방식을 등록 이메일과 일회용 OTP 인증 방식으로 개선한다. 인증된 관리자는 키워드 기사 및 내 스토리 기사 시스템 지침을 수정하고, 버전 이력과 관리자 감사 기록을 확인할 수 있다.

2. 현재 구조와 개선 필요성

현재 로컬 서버는 X-Admin-Password 헤더로 관리자를 검증하고 시스템 지침을 Markdown 파일에 저장한다. Cloudflare Pages는 정적 파일 기반이므로 실행 중인 웹 화면에서 해당 파일을 직접 수정할 수 없다.

OTP 인증만 추가해서는 클라우드 저장 기능이 완성되지 않는다. 서버 측 세션과 시스템 지침용 영구 저장소를 함께 도입해야 한다.

3. 권장 인증 흐름

관리자 이메일 입력 ↓ 등록된 관리자 확인 ↓ 6자리 OTP 생성 및 해시 저장 ↓ 이메일 발송 ↓ OTP 검증 및 즉시 폐기 ↓ 보안 관리자 세션 발급 ↓ 시스템 지침 조회·편집·저장

4. Cloudflare 구성

구성 요소역할
Pages FunctionsOTP 요청·검증, 세션 확인, 관리자 API

5. 데이터 설계

D1

  • admin_users: 관리자 이메일, 상태, 등록 시각, 최근 로그인
  • system_instructions: keyword/story 지침, 버전, 수정자, 수정 시각
  • system_instruction_history: 이전 버전 비교 및 복원
  • admin_audit_logs: 로그인과 중요 변경 작업 기록

KV

  • OTP 해시와 만료 시각
  • 검증 실패 횟수
  • 이메일·IP별 요청 제한
  • 관리자 세션 또는 세션 폐기 정보

6. 보안 정책

항목권장값
OTP암호학적으로 생성한 숫자 6자리
유효시간5분
최대 실패5회
재발송60초 후
이메일별 요청시간당 최대 5회
관리자 세션30~60분
쿠키HttpOnly, Secure, SameSite=Strict
  • OTP 원문은 저장하지 않고 해시값만 저장한다.
  • 관리자 이메일은 프런트엔드 소스에 포함하지 않는다.
  • 등록 여부와 관계없이 OTP 요청 응답을 동일하게 표시한다.
  • Turnstile은 반드시 서버에서 검증한다.
  • 상태 변경 요청에 CSRF 방어를 적용한다.
  • 비밀키는 GitHub에 커밋하지 않는다.

7. 관리자 이메일 등록 정책

공개 화면에서 누구나 최초 관리자 이메일을 등록하게 하면 공격자가 먼저 권한을 가져갈 수 있다.
  1. 최초 이메일은 Cloudflare Secret 또는 D1에 관리자가 직접 등록한다.
  2. 인증된 관리자만 추가 관리자를 등록할 수 있다.
  3. 관리자 변경 시 기존 관리자에게 알림을 발송한다.
  4. 마지막 활성 관리자 계정은 삭제할 수 없게 한다.

9. 시스템 지침 적용

D1 지침 조회 성공 → Gemini API에 즉시 적용 D1 접근 실패 또는 데이터 없음 → 배포된 Markdown 기본 지침 사용

기존 Markdown 파일은 초기값과 장애 복구용으로 유지한다. D1에 저장한 지침은 GitHub를 다시 배포하지 않아도 다음 기사부터 적용한다.

11. 개발 단계

  1. 서버 기반: Pages Functions, D1, KV, Secrets 구성
  2. OTP 인증: 이메일 발송, 검증, Turnstile, 요청 제한, 세션
  3. 지침 이전: Markdown 초기화, D1 저장, Gemini 적용
  4. 관리자 UI: OTP 화면, 넓은 편집기, 이력과 복원
  5. 검증: 만료·재사용·오입력·우회·CSRF·장애 복구 테스트

12. 결론

6자리 이메일 OTP 관리자 인증은 구현 가능하다. 안전하고 완전한 클라우드 관리자 기능을 위해 OTP뿐 아니라 Pages Functions, D1/KV, 서버 세션, 이메일 발송, 시스템 지침 버전 관리를 함께 구현한다.
