Traffic Catcher 서비스 등급 및 기능 권한 관리 기획서

문서 버전 1.0 · 작성·업데이트 2026-08-29 · 시즌 2 개인화·구독형 서비스

1. 목적

회원별 이용 범위를 코드에 고정하지 않고 ADMIN이 관리자 페이지에서 조정한다. 운영 역할과 고객 서비스 등급을 분리하여 보안 권한과 상품 정책이 서로 영향을 주지 않도록 관리한다.

2. 권한 구조

운영 역할(Role)

  • 일반 회원: 일반적인 서비스 이용 계정
  • 유료 회원: 기존 호환을 위해 유지하는 운영 역할
  • 운영자: 회원 지원과 운영 업무 담당
  • 관리자: 회원·서비스 설정을 변경하는 최고 운영 권한

서비스 등급(Plan)

  • Free: 가입·체험 및 기본 이용
  • Plus: 개인화와 충분한 저장 공간을 제공하는 주력 구독
  • Pro: 대량 콘텐츠 제작과 전문 연동을 제공하는 상위 구독

운영 역할은 “누가 관리자 기능을 사용할 수 있는가”를, 서비스 등급은 “고객에게 무엇을 얼마나 제공하는가”를 결정한다.

위 값은 출시 기본값이며 ADMIN이 관리자 페이지에서 즉시 변경할 수 있다. 가격표 문구와 실제 제한값은 같은 설정 데이터를 기준으로 출력하는 구조를 권장한다.

4. 관리자 기능

  1. 회원 목록에서 각 회원의 Free·Plus·Pro 등급을 선택한다.
  2. 서비스 등급별 기능 설정 표에서 숫자, 제공 여부, 모델 범위를 수정한다.
  3. 등급 설정 저장을 누르면 입력값을 검증한 후 한 번에 저장한다.
  4. 저장된 값은 회원의 다음 API 요청부터 적용한다.
  5. 변경 이력은 관리자 감사 로그에 기록한다.

설정값은 정수, Boolean, 선택형으로 구분하며 음수·과도한 값·지원하지 않는 선택값은 서버에서 거부한다.

5. 데이터 구조

  • users.plan_code: 회원에게 적용할 서비스 등급
  • subscription_plans: 등급명, 설명, 정렬 순서, 활성 상태
  • plan_entitlements: 설정 키, 값 형식, 실제 값, 변경자, 변경일
  • admin_audit_logs: 회원 등급·정책 변경 이력

entitlement_key 기반 구조로 새 기능의 설정 키를 추가해 확장한다.

6. 적용 범위

이번 구현에서 회원별 서비스 등급 지정, 내 원고함 최대 저장 개수, 네이버 블로그 로컬 도우미 제공 여부, 로그인 세션을 통한 전체 등급 설정값 전달이 즉시 적용된다.

월 글쓰기 건수는 기존 쿠폰 잔액과 함께 운영한다. 월 기본 건수는 향후 결제 갱신·정기 충전의 기준값이며 트렌드 범위와 개인화 프리셋 제한은 세션 설정값을 이용해 화면과 API에 순차 적용한다.

7. 운영 원칙

  • 제한은 화면뿐 아니라 서버 API에서도 검증한다.
  • 기존 회원은 Free, 기존 유료 역할 회원은 Pro로 1회 마이그레이션한다.
  • ADMIN 자신의 관리자 역할을 해제할 수 없도록 보호한다.
  • 서비스 등급과 운영 역할 변경은 감사 로그에 남긴다.
  • API 키, 글 원문, 완성 글은 등급 설정 로그에 기록하지 않는다.

8. 권장 다음 단계

  1. 결제 상품과 plan_code 매핑
  2. 결제 갱신일에 월 글쓰기 건수 자동 충전
  3. 트렌드 API 단계에서 순위·기간 제한 강제
  4. 지침·페르소나 프리셋 테이블 및 개수 제한
  5. 가격표와 관리자 설정 자동 동기화
  6. 등급 변경 예약·만료·환불·유예 기간을 포함한 구독 이력

9. 완료 기준

  • ADMIN이 회원별 서비스 등급을 변경할 수 있다.
  • Free·Plus·Pro의 모든 제한값과 제공 여부를 저장할 수 있다.
  • 로컬 SQLite와 운영 Cloudflare D1에서 같은 정책이 동작한다.
  • 잘못된 값은 저장되지 않고 오류가 표시된다.
  • 원고 저장 한도와 네이버 도우미 제공 여부가 다음 요청부터 반영된다.
