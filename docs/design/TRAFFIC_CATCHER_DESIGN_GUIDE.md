# Traffic Catcher 화면·디자인 가이드

이 문서는 Traffic Catcher 대시보드와 AI 콘텐츠 스튜디오의 화면 구성, 폰트, 색상, 컴포넌트 및 반응형 규칙을 정리한 유지보수 기준이다.

- 화면 구조: `index.html`, `templates/index.html`
- 디자인 원본: `static/style.css`
- 두 HTML은 정적 Cloudflare 배포와 로컬 Flask 화면에서 같은 UI를 제공해야 한다.

## 1. 디자인 원칙

1. 중요한 제목과 핵심 실행 버튼만 굵게 표시한다.
2. 설명, 출처, 보조 상태와 입력 내용은 보통 또는 가는 굵기로 구분한다.
3. 흰색 카드와 옅은 회색 배경을 기본으로 하고 색상은 상태와 핵심 행동에만 사용한다.
4. 동일한 역할의 버튼은 높이, 폭, 간격과 정렬을 통일한다.
5. 긴 설명은 화면을 점유하지 않도록 커렛이 있는 공통 툴팁으로 제공한다.
6. 모바일에서는 콘텐츠 스튜디오를 전체 화면 작업 공간으로 전환한다.

## 2. 폰트 체계

### 기본 글꼴

```css
--font-sans: 'Inter', 'Noto Sans KR', -apple-system,
             BlinkMacSystemFont, 'Segoe UI', Roboto, sans-serif;
```

- 영문·숫자: `Inter`
- 한글: `Noto Sans KR`
- AI 콘텐츠 스튜디오: `Noto Sans KR` 우선
- 코드 및 원문 영역: `Consolas`, `Courier New`, monospace
- 본문 기본 줄 높이: `1.5`
- 안티앨리어싱: `-webkit-font-smoothing: antialiased`

### 글자 굵기

| 용도 | 권장 굵기 |
|---|---:|
| 페이지 제목, 중요 영역 제목 | 700 |
| 핵심 실행 버튼, 선택된 탭 | 700 |
| 상태 배지, 보조 버튼 | 600 |
| 입력 라벨, 중간 강조 | 500 |
| 설명, 출처, 본문, 보조 정보 | 400 |
| 장식 목적의 과도한 굵기 | 사용하지 않음 |

AI 콘텐츠 스튜디오에서는 일반 정보가 핵심 버튼보다 두드러지지 않도록 본문과 입력 요소를 `400`, 라벨을 `500`, 핵심 제목과 동작을 `600~700`으로 제한한다.

### 목록·데이터 화면 폰트 표준

목록의 데이터명은 사용자가 빠르게 훑어보는 본문 정보이므로 굵게 강조하지 않는다. 순위, 상태, 배지와 핵심 실행 버튼을 통해 정보 계층을 구분한다.

| 화면 요소 | 크기 | 굵기 | 비고 |
|---|---:|---:|---|
| 방송편성표 프로그램명 | `0.78rem` | 400 | 긴 제목은 한 줄 말줄임 |
| 시즌 황금 키워드명 | `0.88rem` | 400 | 카테고리 배지는 별도 강조 |
| 인기검색주식 주식명 | 표 기본 크기 | 400 | 현재가·변동률과 동일한 시각 밀도 유지 |
| 목록의 순위·시간·종목코드 | `0.7~0.78rem` | 400~500 | 보조 정보 색상 사용 |
| 기회지수·시청률 등 수치 | `0.66~0.72rem` | 400~500 | `font-variant-numeric: tabular-nums` 권장 |
| 카테고리·상태 배지 | `0.62~0.7rem` | 500~600 | 색상과 문구를 함께 제공 |
| 목록 내 핵심 실행 버튼 | `0.68~0.78rem` | 600~700 | 목록 제목보다 행동을 명확히 표시 |
| AI 스튜디오 작성 모드 탭 | PC `0.88rem`, 모바일 `0.8rem` | 기본 600, 활성 700 | 활성 탭은 색상과 하단선 함께 사용 |

### 굵기 적용 원칙

- `400`: 본문, 설명, 출처, 프로그램명, 키워드명, 주식명과 일반 데이터
- `500`: 입력 라벨, 순위, 시간, 보조 강조와 작은 데이터 라벨
- `600`: 상태 배지, 선택 상태, 보조 실행 버튼
- `700`: 페이지·영역 제목과 사용자가 눌러야 하는 핵심 실행 버튼
- `800` 이상: 신규 UI에서는 사용하지 않으며, 기존 스타일도 수정 시 `700` 이하로 정리한다.
- 같은 행에서 데이터명과 수치를 모두 굵게 표시하지 않는다.
- 색상만으로 중요도를 표현하지 않고 굵기, 위치, 아이콘 또는 상태 문구를 함께 사용한다.

## 3. 색상 토큰

색상은 가능하면 직접 입력하지 않고 `:root` 변수를 사용한다.

| 토큰 | 값 | 용도 |
|---|---|---|
| `--bg-app` | `hsl(210, 40%, 98%)` | 앱 배경 |
| `--bg-card` | `hsl(0, 0%, 100%)` | 카드·모달 배경 |
| `--text-primary` | `hsl(222, 47%, 11%)` | 제목·주요 본문 |
| `--text-secondary` | `hsl(215, 16%, 47%)` | 설명·보조 정보 |
| `--text-light` | `hsl(213, 27%, 84%)` | 비활성 상태 |
| `--primary` | `hsl(221, 83%, 53%)` | 선택·주요 강조 |
| `--primary-hover` | `hsl(221, 83%, 45%)` | 주요 버튼 hover |
| `--primary-light` | `hsl(221, 83%, 96%)` | 파란색 옅은 배경 |
| `--success` | `hsl(142, 71%, 45%)` | 연결·성공 |
| `--warning` | `hsl(38, 92%, 50%)` | 주의·주목 |
| `--danger` | `hsl(350, 89%, 60%)` | 오류·강한 흥행 강조 |
| `--info` | `hsl(199, 89%, 48%)` | 정보 상태 |
| `--border-color` | `hsl(214, 32%, 91%)` | 기본 경계선 |

### 시청률 색상

- `10% 이상`: 빨간색 배지, 흥행 시청률
- `5~9.9%`: 주황색 배지, 주목 시청률
- `5% 미만` 또는 `집계 전`: 중립 회색 배지
- 현재 기준은 2049가 아닌 전국 가구 시청률이다.

색상만으로 의미를 전달하지 않고 퍼센트 숫자와 기준 툴팁을 함께 제공한다.

## 4. 크기·모서리·그림자

```css
--radius-lg: 16px;
--radius-md: 8px;
--shadow-sm: 0 1px 3px rgba(0,0,0,.05), 0 1px 2px rgba(0,0,0,.02);
--shadow-md: 0 4px 6px -1px rgba(0,0,0,.05), 0 2px 4px -1px rgba(0,0,0,.03);
--shadow-lg: 0 10px 15px -3px rgba(0,0,0,.05), 0 4px 6px -2px rgba(0,0,0,.03);
```

- 주요 카드: `16px` 모서리, `shadow-sm`
- 일반 버튼·입력: `8px` 모서리
- 상태 배지: `999px` 캡슐 모양
- 그림자는 계층 구분에 필요한 최소 수준으로 사용한다.

## 5. 전체 화면 구성

기본 콘텐츠 최대 너비는 `1280px`이며 중앙 정렬한다.

```text
상단 헤더
실시간 검색 키워드
이번 주 방송 편성표
시즌 황금 키워드
인기 주식
푸터
```

- `.app-container`: 최대 `1280px`, PC 여백 `2rem 1.5rem`
- 주요 영역 사이 간격: `2rem`
- 포털 카드: PC 4열, 태블릿 2열, 모바일 1열
- 방송·시즌·주식 영역: 전체 너비 카드
- 방송 편성은 월~일과 채널 분류 탭을 제공하고 방송사별 시간순으로 표시한다.

## 6. 카드와 정보 계층

- 카드 배경은 흰색, 경계선은 `--border-color`를 사용한다.
- 카드 제목은 설명보다 크고 굵게 표시한다.
- 출처, 기준 시각, 보조 설명은 `--text-secondary`와 작은 글자로 표시한다.
- 목록의 순위, 시간, 프로그램명과 수치를 서로 다른 열로 분리한다.
- 데이터가 없을 때 임의 기본값을 만들지 않고 명시적인 빈 상태를 표시한다.

## 7. 버튼 규칙

- 핵심 행동: 채도가 있는 배경과 흰색 글자
- 보조 행동: 흰색 또는 옅은 회색 배경과 같은 색상 계열의 얇은 경계선
- 상태 배지처럼 작게 보이는 클릭 컨트롤: 배경과 같은 계열의 `1px` 경계선
- 클릭할 수 없는 연결·처리 상태 배지: 경계선 없이 배경색과 상태 문구로 구분
- 연결 성공: 녹색 계열
- 삭제·오류: 빨간색 계열
- 버튼은 아이콘과 문구를 중앙 정렬하고 hover 시 `translateY(-1px)` 이내로만 움직인다.
- 비활성 버튼은 채도와 투명도를 낮추고 hover 효과를 제거한다.

### 콘텐츠 스튜디오 하단 버튼

- PC: 영역 너비 `100%`, 5개 버튼을 동일 폭 한 줄로 배치
- 모바일: 동일 폭 2열 배치
- 모바일 버튼 최소 높이: `42px`
- `저장 원고 목록`은 마지막, 오른쪽 위치
- 현재 버튼: 네이버 블로그로 보내기, 마크다운 복사, HTML 양식 복사, HTML 코드 복사, 저장 원고 목록

## 8. 상태 배지

- API 연결 완료와 로컬 도우미 연결 완료는 작은 녹색 캡슐 배지를 사용한다.
- 기준 크기: `font-size: 0.62rem`, `padding: 0.14rem 0.34rem`, `font-weight: 600`
- 상태 배지는 `border: 0`을 기본으로 하며 클릭 가능한 컨트롤과 혼동하지 않게 한다.
- 연결 중은 파란색, 연결 실패는 빨간색 계열을 사용한다.
- 상태 문구 앞에는 `●` 상태점을 사용해 높이가 큰 이모지로 인해 배지가 늘어나지 않게 한다.

## 9. AI 콘텐츠 스튜디오

### PC

- 최대 너비: `1280px`
- 최대 높이: `90vh`
- 본문 영역만 세로 스크롤
- `기사 본문`과 `쇼츠 4컷` 탭 높이: `42px`
- 탭 서브 타이틀은 화면에 표시하지 않고 공통 툴팁으로 제공

### 모바일 (`768px` 이하)

- 모달을 `100% × 100dvh` 전체 화면으로 전환
- 모서리, 외곽 여백과 그림자를 제거
- 헤더는 고정 높이, 본문만 스크롤
- 하단 복사 버튼 영역은 sticky 처리
- 기사 본문 영역은 내부 이중 스크롤을 피한다.

### 네이버 전송 팝업

- PC 최대 너비: `1080px`
- 모바일에서는 화면 너비에서 안전 여백만 제외
- 본문 확인 영역을 충분히 넓게 제공
- 로컬 도우미 연결 상태는 API 연결 완료와 같은 크기의 배지를 사용

## 10. 툴팁

- 긴 설명은 `title` 또는 `data-tooltip` 속성으로 선언한다.
- 전역 스크립트가 이를 `.app-tooltip`으로 변환한다.
- 툴팁에는 대상 중앙을 가리키는 커렛을 표시한다.
- 버튼의 화면 문구는 짧게 유지하고 사용 방법은 툴팁으로 이동한다.
- 키보드 포커스와 마우스 hover 모두에서 확인할 수 있어야 한다.

## 11. 반응형 기준

| 기준 | 주요 변화 |
|---|---|
| `1023px 이하` | 포털 카드 4열에서 2열로 변경 |
| `768px 이하` | 콘텐츠 스튜디오 전체 화면, 소스 목록 재배치 |
| `640px 이하` | 헤더·전송 팝업·목록·버튼 모바일 최적화 |
| `600px 이하` | 포털 카드 1열 |

모바일에서 고정 폭을 사용하지 않는다. 그리드 항목에는 `minmax(0, 1fr)`, 긴 텍스트에는 말줄임이나 줄바꿈을 적용한다.

## 12. 접근성·사용성

- 아이콘만 있는 버튼에는 `aria-label`을 제공한다.
- 탭은 `role="tablist"`, `role="tab"`, `aria-selected`를 사용한다.
- 동적으로 갱신되는 결과는 필요한 경우 `aria-live`를 사용한다.
- 선택 가능한 뉴스는 한 개만 선택하므로 라디오 버튼을 사용한다.
- 색상 강조와 함께 텍스트, 숫자 또는 툴팁을 제공한다.
- `prefers-reduced-motion: reduce` 환경에서는 불필요한 애니메이션을 줄인다.
- 터치 버튼은 모바일에서 최소 `42px`, 주요 행동은 가능하면 `44px` 이상을 확보한다.

## 14. 유지보수 규칙

1. 공통 색상이나 크기를 바꿀 때는 먼저 `:root` 토큰 변경을 검토한다.
2. 같은 역할의 스타일을 새 클래스로 중복 작성하지 않는다.
3. 모바일 규칙은 관련 컴포넌트의 기존 미디어 쿼리 안에 추가한다.
4. 정적 배포와 로컬 화면의 마크업 차이가 생기지 않도록 두 HTML을 동기화한다.
5. 디자인 기준을 변경하면 이 문서와 `static/style.css`를 함께 갱신한다.
