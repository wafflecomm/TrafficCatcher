Traffic Catcher 화면·디자인 가이드

이 문서는 Traffic Catcher 대시보드와 글쓰기 스튜디오의 화면 구성, 폰트, 색상, 컴포넌트, 동작 효과 및 반응형 규칙을 정리한 유지보수 기준이다.

  • 최종 갱신: 2026-08-28

  • 적용 범위: 메인 대시보드, 글쓰기 스튜디오, AI 설정 사이드 패널, 내 프로필, 관리자 화면

  • 화면 구조: index.html, templates/index.html

  • 공통 디자인 원본: static/style.css

  • 기능별 스타일: static/ai-persona.css, static/member-profile.css, static/member-auth.css, static/admin-font.css

  • 화면 전환 동작: static/page-transitions.js

  • 두 HTML은 정적 Cloudflare 배포와 로컬 Flask 화면에서 같은 UI를 제공해야 한다.

1. 디자인 원칙

  1. 중요한 제목과 핵심 실행 버튼만 굵게 표시한다.
  2. 설명, 출처, 보조 상태와 입력 내용은 보통 또는 가는 굵기로 구분한다.
  3. 흰색 카드와 옅은 회색 배경을 기본으로 하고 색상은 상태와 핵심 행동에만 사용한다.
  4. 동일한 역할의 버튼은 높이, 폭, 간격과 정렬을 통일한다.
  5. 긴 설명은 화면을 점유하지 않도록 커렛이 있는 공통 툴팁으로 제공한다.
  6. 모바일에서는 글쓰기 스튜디오를 전체 화면 작업 공간으로 전환한다.
  7. 시간이 걸리는 인증·데이터 조회·페이지 이동은 진행 상태를 즉시 표시하고 완료·실패 상태를 명확히 종료한다.
  8. 수정 가능한 영역과 읽기 전용 규칙은 배지, 배경, 입력 속성으로 명확하게 구분한다.
  9. 애니메이션은 기능 상태를 설명할 때만 사용하며 prefers-reduced-motion 환경을 반드시 지원한다.

2. 폰트 체계

기본 글꼴

--font-sans: 'Inter', 'Noto Sans KR', -apple-system,
             BlinkMacSystemFont, 'Segoe UI', Roboto, sans-serif;
  • 영문·숫자: Inter
  • 한글: Noto Sans KR
  • 글쓰기 스튜디오: Noto Sans KR 우선

  • 사용자가 내 프로필에서 지정한 글꼴은 --tc-user-font, 굵기는 --tc-user-weight로 스튜디오·AI 설정·관리자 화면에 함께 적용
  • 본문 기본 줄 높이: 1.5
  • 안티앨리어싱: -webkit-font-smoothing: antialiased

글쓰기 스튜디오에서는 일반 정보가 핵심 버튼보다 두드러지지 않도록 본문과 입력 요소를 400, 라벨을 500, 핵심 제목과 동작을 600~700으로 제한한다.

목록·데이터 화면 폰트 표준

목록의 데이터명은 사용자가 빠르게 훑어보는 본문 정보이므로 굵게 강조하지 않는다. 순위, 상태, 배지와 핵심 실행 버튼을 통해 정보 계층을 구분한다.

굵기 적용 원칙

  • 400: 본문, 설명, 출처, 프로그램명, 키워드명, 주식명과 일반 데이터
  • 500: 입력 라벨, 순위, 시간, 보조 강조와 작은 데이터 라벨
  • 600: 상태 배지, 선택 상태, 보조 실행 버튼
  • 700: 페이지·영역 제목과 사용자가 눌러야 하는 핵심 실행 버튼
  • 800 이상: 신규 UI에서는 사용하지 않으며, 기존 스타일도 수정 시 700 이하로 정리한다.
  • 같은 행에서 데이터명과 수치를 모두 굵게 표시하지 않는다.
  • 색상만으로 중요도를 표현하지 않고 굵기, 위치, 아이콘 또는 상태 문구를 함께 사용한다.

주요 선택색은 #2563EB(blue-600)를 기준으로 하며 AI 페르소나 설정 타이틀, 글쓰기 모드 선택, 시스템 지침 유형 선택과 주요 실행 버튼에서 같은 계열을 사용한다.

시청률 색상

  • 10% 이상: 빨간색 배지, 흥행 시청률
  • 5~9.9%: 주황색 배지, 주목 시청률
  • 5% 미만 또는 집계 전: 중립 회색 배지
  • 현재 기준은 2049가 아닌 전국 가구 시청률이다.

색상만으로 의미를 전달하지 않고 퍼센트 숫자와 기준 툴팁을 함께 제공한다.

라이트·다크 테마

  • 화면 테마는 시스템 설정, 라이트, 다크 3가지를 제공한다.
  • 로그인 사용자는 user_ui_preferences.theme_mode에 저장하고, 서버 연결 전에는 traffic_catcher_ui_preference 브라우저 캐시를 사용한다.
  • 메인 대시보드와 콘텐츠 스튜디오 상단의 빠른 전환 버튼은 테두리·그림자 없는 원형 플랫 스타일을 사용한다.
  • 콘텐츠 스튜디오의 다크 배경은 #0B1120, 카드 #111827, 보조 카드 #1E293B, 기본 글자 #E5E7EB, 보조 글자 #94A3B8을 기준으로 한다.
  • 블로그 글 미리보기는 실제 발행 화면을 확인하는 용지이므로 전체 테마가 다크여도 흰색 배경과 어두운 글자를 유지한다.
  • 프로필 링과 테마 전환 버튼은 PC와 모바일 모두 독립된 클릭 영역과 최소 간격을 확보한다.

6. 카드와 정보 계층

  • 카드 배경은 흰색, 경계선은 --border-color를 사용한다.
  • 카드 제목은 설명보다 크고 굵게 표시한다.
  • 출처, 기준 시각, 보조 설명은 --text-secondary와 작은 글자로 표시한다.
  • 데이터 수집 주기처럼 여러 안내 항목을 하나로 묶는 정보 영역은 카드형 컨테이너로 보고 1px solid var(--border-color) 외곽선을 표시한다.
  • 출처, 기준 시각, 수집 주기 등 개별 정보가 캡슐형 배지 또는 상태값으로 표시될 때는 border: 0을 적용한다.
  • 목록의 순위, 시간, 프로그램명과 수치를 서로 다른 열로 분리한다.
  • 데이터가 없을 때 임의 기본값을 만들지 않고 명시적인 빈 상태를 표시한다.

클릭 가능한 데이터 행

  • 포털 키워드, 방송 프로그램, 시즌 황금 키워드, 인기 주식처럼 항목 자체가 글쓰기 주제가 되는 목록은 별도 소형 글쓰기 버튼을 반복 배치하지 않고 행 또는 카드 전체를 클릭 영역으로 사용한다.
  • 클릭 전 "선택 항목" 글을 작성하시겠습니까? 확인창을 표시하고 승인된 경우에만 글쓰기 스튜디오를 연다.
  • 마우스 포인터는 pointer, 키보드 접근은 role="button", tabindex="0", Enter·Space 동작을 기본으로 한다.
  • 방송·주식 표 행은 정렬이 움직이지 않도록 hover에서 이동 효과를 쓰지 않고 연한 배경, 내부 1px 테두리, 제목의 --primary 색상만 사용한다.
  • 시즌 키워드 카드는 hover에서 translateY(-1px)과 약한 그림자를 허용하며 클릭 시 원위치로 돌아온다.
  • 시즌 키워드 영역의 PC 좌우 패딩은 방송·주식과 동일한 2rem, 데이터 카드 안쪽 패딩은 0.45rem 0.75rem, 모바일은 각각 0.75rem, 0.5rem을 사용한다.
  • 클릭 영역의 hover·focus 전환 시간은 약 0.18s로 통일하고, focus-visible 상태에서도 동일한 선택 단서를 제공한다.

7. 버튼 규칙

  • 핵심 행동: 채도가 있는 배경과 흰색 글자
  • 보조 행동: 흰색 또는 옅은 회색 배경과 같은 색상 계열의 얇은 경계선
  • 상태 배지처럼 작게 보이는 클릭 컨트롤: 배경과 같은 계열의 1px 경계선
  • 클릭할 수 없는 연결·처리 상태 배지: 경계선 없이 배경색과 상태 문구로 구분
  • 연결 성공: 녹색 계열
  • 삭제·오류: 빨간색 계열
  • 버튼은 inline-flex를 기본으로 사용하고 align-items: center, justify-content: center를 적용하여 아이콘과 문구를 가로·세로 중앙 정렬한다.
  • 모든 클릭 가능한 버튼은 마우스 hover 시 배경색·글자색·테두리색 또는 밝기·채도 중 하나 이상이 명확히 바뀌어야 한다. 위치 이동만으로 hover를 표현하지 않는다.
  • hover 시 위치 이동을 함께 사용할 경우 translateY(-1px) 이내로 제한한다.
  • 클릭할 수 없는 상태 배지와 비활성 버튼에는 hover 색상 변화를 적용하지 않는다.
  • 터치 환경의 hover 잔상을 방지하기 위해 공통 hover 효과는 @media (hover: hover) and (pointer: fine) 범위에서 적용한다.
  • 비활성 버튼은 채도와 투명도를 낮추고 hover 효과를 제거한다.

글쓰기 스튜디오 하단 버튼

  • PC: 영역 너비 100%, 5개 버튼을 동일 폭 한 줄로 배치
  • 모바일: 동일 폭 2열 배치
  • 모바일 버튼 최소 높이: 42px
  • 내 원고함은 마지막, 오른쪽 위치에 배치하고 저장 버튼과 저장 개수 배지를 하나의 복합 컨트롤로 표시한다.
  • 현재 버튼: 네이버 글쓰기 열기, 글 서식 복사, HTML 코드 복사, 마크다운 복사, 내 원고함
  • 네이버 글쓰기 열기는 공식 네이버 블로그 아이콘과 흰색 배경·네이버 그린 테두리로 외부 서비스 이동 기능임을 구분한다.
  • 글 서식 복사는 중립적인 슬레이트 그레이 계열로 표시해 네이버 이동 버튼과 시각적 우선순위가 겹치지 않게 한다.
  • 내 원고함은 로그인 계정 DB에 최근 원고 최대 5개를 스택 방식으로 저장한다.

8. 상태 배지

  • API 연결 완료는 작은 녹색 캡슐 배지를 사용한다.
  • 기준 크기: font-size: 0.62rem, padding: 0.14rem 0.34rem, font-weight: 600
  • 상태 배지는 border: 0을 기본으로 하며 클릭 가능한 컨트롤과 혼동하지 않게 한다.
  • 상태 배지의 무테두리 규칙은 개별 상태값에만 적용하며, 여러 정보를 묶는 안내 컨테이너의 외곽선에는 적용하지 않는다.
  • 연결 중은 파란색, 연결 실패는 빨간색 계열을 사용한다.
  • 상태 문구 앞에는 ● 상태점을 사용해 높이가 큰 이모지로 인해 배지가 늘어나지 않게 한다.

AI 연결 경로 앰비언트 표시

  • 사용자에게 보이는 연결 문구는 경로와 관계없이 AI 연동으로 통일한다. 한국 서버 경유, 프록시 주소와 같은 내부 연결 정보는 일반 화면에 직접 표시하지 않는다.
  • 관리자가 한국 서버 경유를 선택했고 실제 연결 확인까지 성공한 경우에만 파란색 앰비언트 라인이 상태 요소의 테두리를 시계방향으로 순환한다.
  • 동일한 연결 상태는 API 연동 설정 버튼과 글쓰기 버튼 바로 위의 작은 AI 연동 상태 배지에 함께 적용한다. 두 요소의 문구, 성공 색상과 회전 속도는 일관되게 유지한다.
  • 테두리는 conic-gradient와 마스크를 사용해 내용 및 녹색 성공 배경을 가리지 않는 약 1.5px 라인으로 표현하고, 회전 주기는 2.8초를 기준으로 한다.
  • Cloudflare 직접 연결, 연결 확인 중, 연결 실패, 로그아웃 상태에서는 앰비언트 효과를 제거한다. 실패 상태는 기존 빨간색 배지만 사용한다.
  • prefers-reduced-motion: reduce에서는 회전을 중지하고 정지된 테두리로 연결 경로를 구분한다.

8.1 아이콘 시스템 — Lucide Icons

  • 서비스 공통 UI 아이콘은 Lucide Icons를 기본으로 사용한다.
  • 현재 웹 적용 버전은 1.35.0으로 고정하며 unpkg의 UMD 빌드와 static/lucide-icons.js 초기화 도우미를 사용한다.
  • 홈, 뒤로가기, 설정, 검색, 복사, 삭제, 펼치기처럼 기능을 설명하는 아이콘은 Lucide로 통일한다.
  • YouTube·네이버 등 서비스 로고, 트래픽캐쳐 브랜드 이미지, 데이터 그래프와 상태 시각화는 Lucide로 대체하지 않는다.
  • 신규 기능 버튼에 이모지를 기능 아이콘 대신 사용하지 않는다. 축제·상태처럼 의미를 보조하는 장식 이모지는 허용한다.
  • 기존 화면의 브랜드 제목, 영역 제목, 작성 모드 탭, 설정·복사·삭제·새로고침·원고함·테마 버튼은 Lucide로 전환한다. 실시간 이슈의 불꽃·번개, 성공·경고 상태, 문화 장르와 생성된 글 본문처럼 데이터 의미를 가진 표시는 전환 대상에서 제외한다.
  • 기본 크기는 본문 버튼 18px, 소형 버튼 16px, 단독 탐색 버튼 20~24px로 한다. 선 굵기는 기본 2, 보조 정보는 1.75를 권장한다.
  • 아이콘 색상은 고정 색상 대신 currentColor를 사용해 라이트·다크 모드와 버튼 상태를 자동으로 따른다.

정적 HTML에서 사용

페이지 <head>에서 버전이 고정된 라이브러리와 공통 초기화 파일을 순서대로 불러온다.

<script src="https://unpkg.com/lucide@1.35.0/dist/umd/lucide.min.js" defer></script>
<script src="/static/lucide-icons.js?v=20260828-1" defer></script>

버튼이나 링크에는 아이콘 이름만 선언한다. 초기화 스크립트가 <i>를 Lucide SVG로 변환한다.

<button type="button" class="icon-text-button">
  <i data-lucide="copy"></i>
  <span>글 서식 복사</span>
</button>

<a href="/" class="icon-only-button" aria-label="홈으로 이동">
  <i data-lucide="house"></i>
</a>

JavaScript로 동적 요소를 추가할 때

동적 HTML을 삽입한 직후 해당 컨테이너만 다시 변환한다. 전체 DOM을 감시하는 MutationObserver는 성능과 중복 렌더링 문제 때문에 사용하지 않는다.

container.innerHTML = '<i data-lucide="trash-2"></i><span>삭제</span>';
window.TrafficCatcherIcons?.refresh(container);

접근성 규칙

  • 문구와 함께 쓰는 장식 아이콘은 공통 초기화 과정에서 aria-hidden="true", focusable="false"로 처리한다.
  • 아이콘만 있는 버튼·링크에는 반드시 동작을 설명하는 aria-label과 공통 툴팁을 제공한다.
  • 로딩, 성공, 실패처럼 중요한 상태는 아이콘이나 색상만으로 표현하지 않고 상태 문구를 함께 표시한다.
  • 아이콘 자체에는 클릭 이벤트를 연결하지 않고 아이콘을 포함한 <button> 또는 <a>를 클릭 대상으로 사용한다.

라이선스·운영 기준

  • Lucide는 ISC 라이선스의 오픈소스 아이콘 라이브러리다.
  • 운영 장애를 줄이기 위해 @latest를 사용하지 않고 검증된 버전을 고정한다.
  • 버전을 변경할 때는 메인 대시보드, AI 글쓰기 스튜디오, 내 프로필과 관리자 화면에서 아이콘 누락 및 정렬을 확인한 뒤 모든 페이지의 버전을 함께 갱신한다.

9. AI 글쓰기 스튜디오

PC

  • 대시보드와 동일한 최대 너비 1280px를 사용한다.
  • 왼쪽에는 테두리 없는 뒤로가기 화살표, 오른쪽에는 사용자 프로필과 남은 글쓰기 횟수 링을 배치한다.
  • 중앙 상단의 AI 페르소나·톤앤매너 설정은 #2563EB 배경을 사용하고 ON/OFF 상태를 함께 표시한다.
  • 키워드·뉴스와 메모·스토리는 동일 폭의 작성 모드 선택 탭으로 제공한다.
  • 출력물은 글 본문, 삽화 4컷, 쇼츠 4컷 3개 탭으로 구분하고 회색 계열 배경을 사용해 상단 작성 옵션과 시각적으로 분리한다.
  • 글 본문에는 블로그 글 미리보기만 표시하며 최근 글 불러오기 버튼을 유지한다.
  • 최근 글 불러오기는 현재 선택한 키워드·뉴스 또는 메모·스토리 작성 모드를 바꾸지 않고 출력물만 현재 화면에 복원한다.
  • 삽화 4컷과 쇼츠 4컷 출력 영역 아래에는 프롬프트를 복사해 이미지 생성 AI에 전달하는 활용 방법을 엷은 안내문으로 표시한다. 안내문은 연한 회색 배경, 1px 테두리, 본문보다 작은 글자로 구분한다.
  • 본문 영역만 세로 스크롤하며 내부 이중 스크롤을 만들지 않는다.
  • 탭 서브 타이틀은 화면을 점유하지 않고 공통 툴팁으로 제공한다.

모바일 (768px 이하)

  • 스튜디오를 100% × 100dvh 전체 화면 작업 공간으로 전환
  • 모서리, 외곽 여백과 그림자를 제거
  • 헤더는 고정 높이, 본문만 스크롤
  • 하단 복사 버튼 영역은 sticky 처리
  • 글 본문 영역은 내부 이중 스크롤을 피한다.

네이버 글쓰기 연결

  • 별도 팝업 없이 하단 액션 버튼에서 서식 복사와 글쓰기 화면 열기를 한 번에 실행한다.
  • 버튼 문구는 네이버 글쓰기 열기로 간결하게 유지하고, HTML 리치 서식 복사·붙여넣기·최종 발행 안내는 커렛 툴팁으로 제공한다.
  • 관리자 계정의 내 프로필에는 네이버 글쓰기 기능 ON/OFF 스위치를 표시한다. 스위치를 꺼도 설정 영역은 사라지지 않으며 상태만 사용 중 또는 사용 안 함으로 바뀐다.
  • 설정은 관리자 계정별 DB에 저장하며 글쓰기 페이지와 내 원고함의 네이버 글쓰기 버튼에 즉시 반영한다.

AI 페르소나·톤앤매너

  • 현재 선택한 세부 주제와 페르소나를 첫 줄의 핵심 정보로 표시한다.
  • 설정 명칭과 ON/OFF 상태는 두 번째 줄의 보조 정보로 표시한다.
  • 사용 중 상태에는 절제된 펄스 효과를 허용하고, 사용 안 함은 중립 회색으로 표시한다.
  • 카테고리, 세부 주제, 페르소나, 말투 강도, 글의 밀도와 추가 지침은 계정 DB에 저장한다.

10. 툴팁

  • 긴 설명은 title 또는 data-tooltip 속성으로 선언한다.
  • 전역 스크립트가 이를 .app-tooltip으로 변환한다.
  • 툴팁에는 대상 중앙을 가리키는 커렛을 표시한다.
  • 버튼의 화면 문구는 짧게 유지하고 사용 방법은 툴팁으로 이동한다.
  • 키보드 포커스와 마우스 hover 모두에서 확인할 수 있어야 한다.

11. AI 시스템 지침 통합 관리

AI 시스템 지침 관리 화면은 왼쪽에서 열리는 사이드 패널이며 다음 네 단계를 실제 AI 전달 순서와 동일하게 표시한다.

1. 절대 규칙 → 2. 선택 글쓰기 유형 →
3. 페르소나·톤앤매너 → 4. 지침 충돌 해결 규칙

권한과 표현

단계 표시 방식 편집 권한
절대 규칙 접이식 카드, 읽기 전용 회색 배지 수정 불가
선택 글쓰기 유형 기본 펼침 카드, 편집 가능 녹색 배지 계정 DB 저장 가능
페르소나·톤앤매너 접이식 카드, 사용 중/사용 안 함 배지 현재 설정값 조회만 가능
지침 충돌 해결 규칙 접이식 카드, 읽기 전용 회색 배지 수정 불가
  • 읽기 전용 규칙은 disabled가 아닌 readonly를 사용하여 선택과 복사는 허용한다.
  • 파일 불러오기, 드래그앤드롭, 기본값 불러오기, DB에서 불러오기, 저장 및 즉시 적용은 2단계에서만 제공한다.
  • 개인 DB 지침이 없으면 개인 지침 없음 · AI API에 빈 값 전달 상태를 표시한다.
  • 기본값은 자동 적용하지 않으며 사용자가 기본값 불러오기 후 계정 DB에 저장한 경우에만 개인 지침으로 전달한다.
  • 필수 출력 형식인 삽화 4컷·쇼츠 4컷 규칙은 절대 규칙의 읽기 전용 하위 규칙으로 표시한다.

글쓰기 유형 선택 카드

  • 키워드·뉴스와 메모·스토리를 동일 폭 2열 세그먼트 카드로 표시한다.
  • PC 최소 높이는 54px, 모바일은 48px이다.
  • 각 카드에는 아이콘, 유형명, 한 줄 설명을 배치한다.
  • 선택 카드는 #2563EB 배경, 흰색 글자, ✓ 선택됨 문구와 약한 파란 그림자를 사용한다.
  • 비선택 카드는 회색 배경 위 투명 카드로 두고 hover에서만 흰색 계열로 밝아진다.
  • 모바일에서는 공간 확보를 위해 선택됨 보조 문구를 숨기되 파란 배경은 유지한다.
  • 유형 설명은 각 선택 카드 안에서만 제공하고 탭 오른쪽에 별도의 설명·출처 영역을 두지 않는다.
  • DB 불러오기, 기본값 적용과 저장 결과는 편집기 하단의 상태 메시지에서 안내한다.

12. 동작 효과와 진행 상태

공통 페이지 전환

  • 페이지 진입 시 opacity: 0 → 1, translateY(10px) → 0으로 자연스럽게 표시한다.
  • 페이지 이탈 시 opacity: 1 → 0, translateY(0) → -8px을 사용한다.
  • 전환 효과는 콘텐츠 이해를 방해하지 않도록 약 0.24~0.34초 범위로 제한한다.

글쓰기 페이지 전환 진행 바

  • 인증 상태 확인을 시작하는 즉시 화면 상단에 진행 바와 글쓰기 페이지를 준비하고 있습니다 문구를 표시한다.
  • PC 높이 4px, 모바일 높이 3px, 색상은 #2563EB → #60A5FA → #8B5CF6 그라데이션을 사용한다.
  • 이동 중 진행률은 8% → 84%까지 단계적으로 증가하고, 스튜디오 준비 완료 시 100%로 완료한 뒤 약 0.52초 안에 사라진다.
  • 로그인 실패나 접근 권한 부족 시 즉시 종료하고 남은 진행 상태를 제거한다.
  • 브라우저 뒤로가기로 이전 화면이 BFCache에서 복원될 때 pageshow에서 진행 클래스와 sessionStorage 이동 표식을 반드시 초기화한다.

실시간 모니터링 앰비언트 테두리

  • 4대 포털 통합 핫이슈 영역은 파란색 conic-gradient가 테두리를 순환하여 실시간 모니터링 상태를 표현한다.
  • 기본 상태는 9초, 수집 중은 3.2초, 수집 완료 초록 상태는 1.4초 회전으로 구분한다.
  • 수집 실패는 회전하지 않는 빨간색 테두리로 표시한다.
  • 모바일은 기본 12초, 수집 중 4.2초로 낮추고 밝기도 줄인다.
  • prefers-reduced-motion: reduce에서는 회전을 중지한다.

입력 강조 앰비언트 효과

  • 메모·스토리의 핵심 본문 입력처럼 사용자의 주 입력이 필요한 곳에만 회전하는 앰비언트 테두리를 허용한다.
  • 인접 입력 요소에는 강한 보라색 테두리를 중복 사용하지 않아 핵심 입력의 강조를 보존한다.
  • 앰비언트 효과는 오류, 선택, 필수 상태를 대신하지 않으며 라벨과 안내 문구를 함께 제공한다.

600px 이하 포털 카드 1열

모바일에서 고정 폭을 사용하지 않는다. 그리드 항목에는 minmax(0, 1fr), 긴 텍스트에는 말줄임이나 줄바꿈을 적용한다.

14. 관리자 AI API 연결 설정

  • AI API 연결 방식은 관리자에게만 표시하며 Cloudflare 직접 연결과 한국 서버 경유를 동일한 선택 카드로 제공한다.
  • 한국 서버 경유 연결이 정상일 때도 문구는 일반 연결과 동일한 AI 연동으로 표시한다. 관리자 구분용 앰비언트 라인은 API 연동 설정 버튼과 글쓰기 버튼 위 상태 배지에 동시에 적용한다. 직접 연결·확인 중·실패 상태에는 효과를 사용하지 않으며 prefers-reduced-motion 환경에서는 정지된 테두리로 대체한다.
  • 한국 서버 중계 환경변수가 준비되지 않은 경우 빨간색 서버 설정 필요 상태를 표시하고 해당 모드 저장을 차단한다.
  • 연결 방식 선택값은 운영 설정 DB에 저장하고 다음 글쓰기 요청부터 적용한다.
  • API 키, 중계 URL 원문 및 인증 토큰은 관리자 UI에도 노출하지 않는다.

15. 접근성·사용성

  • 아이콘만 있는 버튼에는 aria-label을 제공한다.
  • 탭은 role="tablist", role="tab", aria-selected를 사용한다.
  • 동적으로 갱신되는 결과는 필요한 경우 aria-live를 사용한다.
  • 선택 가능한 뉴스는 한 개만 선택하므로 라디오 버튼을 사용한다.
  • 색상 강조와 함께 텍스트, 숫자 또는 툴팁을 제공한다.
  • prefers-reduced-motion: reduce 환경에서는 불필요한 애니메이션을 줄인다.
  • 진행 바는 장식만으로 끝내지 않고 aria-busy 상태와 진행 안내 문구를 함께 제공한다.
  • 페이지 복원 시 남은 로딩 상태를 제거하여 화면이 계속 처리 중인 것으로 오인되지 않게 한다.
  • 터치 버튼은 모바일에서 최소 42px, 주요 행동은 가능하면 44px 이상을 확보한다.
  • 글쓰기 실행 버튼 위에는 연동 상태와 현재 모델 선택을 한 줄의 컴팩트 런타임 정보로 묶는다. 모델은 서버 allowlist의 선택지만 노출하고 변경값은 다음 생성 요청부터 적용한다.
  • 글쓰기 모델은 라이트·스탠다드·프리미엄 메타데이터를 함께 관리한다. 현재는 사용자가 자유롭게 선택하되, 향후 회원 요금제별 모델 권한과 사용 크레딧 차등을 서버에서 적용할 수 있는 구조를 유지한다.
  • 모델 선택 컨트롤은 기본 브라우저 셀렉트 외형을 그대로 노출하지 않고 ✦ 아이콘, AI 모델 라벨, 커스텀 화살표를 포함한 캡슐형 트리거로 표시한다. 트리거를 누르면 프로필 사진 메뉴와 같은 흰색 팝오버 목록이 열리며, 각 모델의 용도 설명과 현재 선택 체크를 함께 제공한다. 라이트는 옅은 하늘색, 스탠다드는 파란색, 프리미엄은 보라색 계열로 구분하되 본문보다 과도하게 강조하지 않는다.
  • 모델 팝오버는 글쓰기 버튼 아래의 스크롤 영역을 늘리지 않도록 트리거 위쪽으로 연다. 모델 UI는 글 본문 MutationObserver와 분리해 명시적인 초기화·화면 렌더링 시점에만 생성하며, API 상태 확인은 동일 요청을 재사용하고 모델 변경 시 이전 요청을 취소한다.
  • 글쓰기 버튼 위의 AI 연동 문구는 실패할 때만 빨간 상태 배지로 표시한다. 정상 연결은 별도 문구를 노출하지 않으며, 한국 서버 경유 상태는 모델 선택 컨트롤의 회전형 앰비언트 테두리만으로 운영자가 구분한다.
  • AI 시스템 지침 관리의 최종 전달 순서는 각 규칙 앞 체크박스로 포함 여부를 조합한다. ai.personalize 권한이 있는 로그인 사용자가 자신의 구성을 변경하며 사용자 ID별 서버 DB에 저장한다.
  • 전달 구성은 체크박스 변경 즉시 저장한다. 별도 저장 버튼을 두지 않고 처리 중·완료·실패 상태를 체크박스 아래 안내 문구로 보여준다. 저장 중에는 중복 요청 방지를 위해 체크박스를 잠시 비활성화하고, 실패하면 DB 저장값으로 복구한다.
  • AI 시스템 지침 관리 필요 상태는 키워드·뉴스와 메모·스토리 지침을 동시에 검사하지 않는다. 현재 선택한 글쓰기 탭의 개인 지침만 확인하고, 탭 전환 시 해당 유형의 상태를 즉시 다시 계산한다.

17. 유지보수 규칙

  1. 공통 색상이나 크기를 바꿀 때는 먼저 :root 토큰 변경을 검토한다.
  2. 같은 역할의 스타일을 새 클래스로 중복 작성하지 않는다.
  3. 모바일 규칙은 관련 컴포넌트의 기존 미디어 쿼리 안에 추가한다.
  4. 정적 배포와 로컬 화면의 마크업 차이가 생기지 않도록 두 HTML을 동기화한다.
  5. 디자인 기준을 변경하면 이 문서와 static/style.css를 함께 갱신한다.
  6. 페이지 전환 효과를 변경하면 static/page-transitions.js의 시작·완료·실패·BFCache 복원 경로를 함께 검사한다.
  7. AI 설정 UI를 변경하면 실제 system_instruction 조립 순서와 화면의 단계 번호가 일치하는지 확인한다.
