AI API 한국 서버 경유 설정 가이드

TrafficCatcher Cloudflare Worker와 Oracle 한국 서버 인증 프록시 연결 구성

● 2026-08-27 운영 연결 확인 완료

1. 동작 구조

로그인 사용자 → Cloudflare Worker 권한·쿠폰 확인 → Oracle 인증 프록시 → AI API

관리자는 Cloudflare 직접 연결과 한국 서버 경유 중 하나를 선택합니다. 선택값은 D1의 service_settings.ai_route에 저장되고, 한국 서버 경유가 선택된 경우에만 Oracle 프록시를 호출합니다.

2. 정상 운영 구성

3. IP 주소 직접 호출 금지

Cloudflare Worker 외부 요청에는 IP 주소를 직접 사용하지 않습니다. 다음 주소는 403의 원인이므로 사용하지 않습니다.

http://152.67.192.37:3000/api/proxy

Cloudflare DNS에 다음 레코드를 등록합니다.

4. Cloudflare 환경변수

GEMINI_API_KEY=<AI API 키>
KOREA_AI_PROXY_URL=http://kr-proxy.trafficcatcher.ai:3000/api/proxy
KOREA_AI_PROXY_KEY=<프록시 x-api-key>
KOREA_AI_PROXY_ALLOW_INSECURE=true

키 값은 Secret으로 저장하고 Production 환경에 적용한 뒤 새 배포를 실행합니다. 소스·로그·브라우저에는 실제 값을 노출하지 않습니다.

5. Worker 사용자 지정 포트

wrangler.toml에 다음 값을 유지합니다.

compatibility_flags = ["allow_custom_ports"]

3000번 포트는 Cloudflare 프록시 대상 포트가 아니므로 DNS 레코드를 주황색 구름으로 전환하면 안 됩니다.

6. 관리자 설정과 화면 표시

  1. 관리자 페이지의 AI API 연결 방식에서 한국 서버 경유를 선택합니다.
  2. 연결 방식 저장을 누릅니다.
  3. 콘텐츠 스튜디오에서 API 연결 상태를 확인합니다.

연결 응답의 route가 korea_relay여도 화면에는 일반 연결과 동일한 API 연동 문구만 표시합니다. 관리자는 버튼 테두리를 따라 시계방향으로 도는 파란색 앰비언트 라인으로 경유 상태를 구분합니다. 직접 연결과 실패 상태에는 효과가 나타나지 않습니다.

8. 보안 개선

현재 HTTP 구성에서는 인증키와 요청 내용이 암호화되지 않습니다. 장기 운영에서는 Oracle 서버 앞에 Nginx 또는 Caddy를 구성해 HTTPS 443으로 전환하고 KOREA_AI_PROXY_ALLOW_INSECURE를 제거해야 합니다.
  • 프록시 대상 호스트를 generativelanguage.googleapis.com으로 제한
  • 요청 크기·타임아웃·속도 제한 적용
  • 노출된 프록시 인증키 재발급
  • 프롬프트와 API 키를 서버 로그에 기록하지 않음
