# Traffic Catcher 서비스 등급·가격·권한 운영 기획서

- 문서 버전: 1.1
- 최종 갱신일: 2026-08-30
- 적용 범위: 시즌 2 개인화·구독형 서비스

## 1. 목적

일반 회원과 유료 회원에게 제공할 기능·사용량·저장 한도를 명확히 구분하고, 가격과 제공 범위를 코드에 고정하지 않고 관리자가 변경할 수 있게 한다. 운영 권한과 고객 상품 등급을 분리하여 보안 설정과 결제 정책이 서로 간섭하지 않도록 한다.

## 2. 권한 구조

### 운영 역할(Role)

- 일반 회원(`member`): 일반 서비스 이용 계정
- 운영자(`operator`): 회원 지원과 제한된 운영 업무
- 관리자(`admin`): 회원·결제·서비스 정책을 변경하는 최고 권한
- 기존 `premium` 역할은 데이터 호환용으로만 유지하고 신규 유료 여부 판단에는 사용하지 않는다.

### 서비스 등급(Plan)

- Free: 가입·체험과 기본 이용
- Plus: 개인 블로그 운영자를 위한 주력 유료 상품
- Pro: 다량 작성, 전문 모델 및 로컬 연동을 위한 상위 상품

운영 역할은 “관리 기능을 누가 사용할 수 있는가”를 결정하고, 서비스 등급은 “고객에게 무엇을 얼마나 제공하는가”를 결정한다.

## 3. 출시 권장 가격

| 구분 | Free | Plus | Pro |
|---|---:|---:|---:|
| 월간 결제 | 무료 | 9,900원 | 19,900원 |
| 연간 결제 | 무료 | 99,000원 | 199,000원 |
| 연간 할인 효과 | - | 약 2개월 무료 | 약 2개월 무료 |
| 핵심 고객 | 체험 사용자 | 개인 블로거 | 전문·다량 콘텐츠 운영자 |

회원에게 표시하는 가격은 부가세 포함 금액으로 통일한다. AI API 비용을 서비스가 전액 부담하고 고성능 모델 사용 비중이 높아지면 Plus 12,900원, Pro 29,900원까지 조정할 수 있도록 관리자 설정값으로 관리한다.

## 4. 기본 제공 정책

| 기능 | Free | Plus | Pro |
|---|---:|---:|---:|
| 월 글쓰기 | 10건 | 50건 | 200건 |
| 미완의 글서랍 | 10개 | 100개 | 500개 |
| AI 시스템 지침서 | 2개 | 10개 | 30개 |
| AI 페르소나 | 1개 | 5개 | 20개 |
| 포털 트렌드 순위 | 10위 | 20위 | 50위 |
| 과거 트렌드 | 미제공 | 최근 30일 | 최근 90일 |
| 네이버 검색어 트렌드 | 제공 | 제공 | 제공 |
| 방송·시즌·주식 정보 | 제공 | 제공 | 제공 |
| 트렌드 내보내기 | 미제공 | 제공 | 제공 |
| AI 모델 | Lite | Flash 포함 | 전체 공개 모델 |
| 네이버 블로그 로컬 도우미 | 미제공 | 미제공 | 제공 |

무료 회원에게 데이터 종류 자체를 과도하게 숨기지 않고, 순위 깊이·과거 데이터·저장량·개인화·전문 연동에서 차이를 둔다.

## 5. 글쓰기 건수 정책

- 글쓰기 결과가 정상 완료된 경우에만 1건을 차감한다.
- 오류, 시간 초과, 사용자 취소 및 서버 중단은 차감하지 않거나 자동 환불한다.
- 뉴스 팩트 다시 수집, 저장, 복사, 불러오기는 차감하지 않는다.
- 완성 글을 다시 생성하는 요청은 1건을 차감한다.
- 향후 고성능 모델은 2건 이상을 차감할 수 있지만, 실행 전에 사용량을 명확히 표시한다.
- 월 제공량과 별도로 관리자 쿠폰 및 프로모션 지급량을 합산한다.

## 6. 관리자 설정

관리자는 `서비스 등급별 기능 설정`에서 다음 값을 변경한다.

- 요금제 판매 여부
- 월간·연간 결제 금액
- 월 기본 글쓰기 건수
- 미완의 글서랍 저장 개수
- 개인 시스템 지침 및 페르소나 저장 개수
- 포털 순위 및 과거 조회 기간
- 데이터 종류별 제공 여부
- 데이터 내보내기 및 네이버 로컬 도우미 제공 여부
- AI 모델 제공 범위

회원 관리에서는 서비스 등급, 계정 상태, 잔여 글쓰기 건수와 쿠폰을 별도로 관리한다. 서비스 등급 정책 변경과 회원별 등급 변경은 감사 로그에 기록한다.

## 7. 결제 화면 원칙

- 내 프로필은 관리자 설정에서 판매 중인 요금제만 조회한다.
- 현재 등급, 월·연간 가격과 월 글쓰기 제공량을 표시한다.
- 현재 등급보다 높은 상품만 업그레이드 대상으로 제공한다.
- 결제 기능이 `미사용`이면 기존처럼 `베타 테스트 중입니다.`라고 안내한다.
- 결제대행사 연결 후 선택한 `plan_code`를 결제 요청에 전달한다.
- 가격표와 실제 제한값은 동일한 DB 설정을 사용하여 불일치를 방지한다.

## 8. DB 및 API 구조

- `users.plan_code`: 회원에게 적용된 Free·Plus·Pro 등급
- `subscription_plans`: 상품명, 설명, 표시 순서 및 활성 상태
- `plan_entitlements`: 가격, 판매 여부, 저장량, 이용량 및 기능 제공 범위
- `role_feature_permissions`: 운영 역할별 화면·관리 API 접근 권한
- `admin_audit_logs`: 관리자 정책 변경 이력
- `GET /api/auth/plans`: 회원 화면용 판매 요금제 조회
- `GET/PATCH /api/admin/service-plans`: 관리자 등급 정책 조회·저장

## 9. 운영 지표

출시 후 최소 3개월 동안 다음 지표를 월별로 확인한다.

- Free에서 Plus로의 전환율
- Plus에서 Pro로의 전환율
- 회원당 월평균 글쓰기 완료 건수
- AI 요청 1건당 평균 원가와 실패율
- 월 구독 해지율과 환불률
- 저장 기능, 시스템 지침, 페르소나 사용률

API 가격과 결제 수수료가 변경될 수 있으므로 영구 할인이나 평생 고정 가격은 피하고 분기별로 원가와 한도를 검토한다.
