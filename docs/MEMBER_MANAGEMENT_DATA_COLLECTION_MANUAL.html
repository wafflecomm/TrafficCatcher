Traffic Catcher 회원 관리·데이터 수집 운영 매뉴얼

최종 갱신 2026-08-29최고 관리자운영 담당자장애 대응 담당자

회원 권한과 글쓰기 사용량을 개인정보 침해 없이 관리하고, 운영 데이터의 정상 수집 여부를 확인해 장애를 빠르게 복구하는 실무 절차다.

1. 운영 전 확인

로컬

  1. 실행_웹서버.bat을 실행한다.
  2. 회원 DB 파일과 .env가 있는지 확인한다.
  3. 관리자 계정으로 로그인한다.
  4. 관리자 페이지의 회원 요약과 목록 로딩을 확인한다.

운영

  1. 운영 도메인에 접속한다.
  2. 관리자 계정으로 이메일 OTP 로그인한다.
  3. 내 프로필에서 관리자 페이지를 연다.
  4. Cloudflare D1 AUTH_DB와 Worker 연결 상태를 확인한다.
비밀키와 인증 토큰은 화면 캡처, 문서, 메신저, 장애 티켓에 붙여넣지 않는다.

2. 관리자 화면 구성

영역확인·변경 내용
운영 요약전체 회원·등급·이용 상태 집계
회원 목록닉네임·이메일·가입·최근 로그인·등급·상태·가능 건수
회원 상세계정·사용량·최근 실행·관리 변경 내역
AI 실행 경로Cloudflare 직접 또는 한국 서버 중계
뉴스 검색 방식네이버·Google News와 보완 순서
AI 모델노출 모델과 기본 모델
역할별 권한대시보드·글쓰기·개인화·결제·관리자 기능

회원 행을 누르면 아코디언 상세가 열린다. 변경 전 대상 이메일과 닉네임을 다시 확인한다.

3. 회원 정보 확인

계정

  • 회원 ID, 이메일, 닉네임
  • 일반·유료·운영자·관리자 등급
  • 정상 또는 이용 정지 상태
  • 가입·이메일 인증·최근 로그인·최근 변경 시각

글쓰기 이용 현황

표시해석
현재 가능일반 회원의 남은 글쓰기 건수
누적 지급·누적 사용쿠폰 지급과 사용 원장
저장 원고내 원고함 저장 수
전체 글쓰기·완료·실패상태별 실행 수
이번 달 실행·사용량월간 운영 지표
누적 사용량무제한 회원을 포함한 총 실행 단위

유료·운영자·관리자는 무제한으로 표시되지만 비용과 품질 관리를 위해 실행 횟수는 집계한다.

4. 회원 등급과 상태 변경

유료회원 등록

  1. 대상 이메일과 닉네임을 확인한다.
  2. 회원 등급을 유료 회원으로 선택한다.
  3. 이용 상태가 정상인지 확인한다.
  4. 권한 저장을 누른다.
  5. 상세 영역에서 등급과 관리자 변경 내역을 재확인한다.
결제대행사 자동 연동 전이므로 유료회원 지정과 회수는 운영자 승인에 따른 수동 작업이다. 종료일 자동 회수 기능은 아직 없다.

이용 정지

  1. 약관·보안 사유와 근거를 확인한다.
  2. 대상 계정을 이용 정지로 변경한다.
  3. 사유를 운영 기록에 남긴다.
  4. 복구 시 본인 확인 후 정상으로 되돌린다.

관리자 자신의 최고 권한 또는 정상 상태는 화면에서 해제할 수 없다.

5. 글쓰기 가능 건수 관리

  1. 일반 회원의 현재 가능 건수를 확인한다.
  2. 새 잔액을 입력한다.
  3. 저장한다.
  4. 상세 화면의 현재 가능·누적 지급·누적 사용과 변경 내역을 확인한다.

결제 보상, 장애 보상, 프로모션, 운영 정정 중 하나로 사유를 구분해 내부 기록을 남기는 것을 권장한다. 무제한 등급은 잔액보다 실제 사용량을 확인한다.

6. 최근 글쓰기 실행내역

새 글·글 보완, 키워드·스토리 모드, 모델, 실행 환경, 자료 유형, 입력·출력 글자 수, 처리 시간, 사용량, 차감·환불, 상태, 안전한 오류 코드만 표시한다.

코드의미조치
TIMEOUT시간 초과모델·중계·네트워크 확인
AI_CAPACITY제공업체 혼잡재시도·모델 상태 확인
NETWORK연결 오류방화벽·DNS·외부 연결 확인
AI_AUTHAPI 인증 오류Secret·API 활성화 확인
CREDIT_REQUIRED건수 부족회원 잔액·등급 확인
UPSTREAM_HTTP_*외부 AI HTTP 오류상태 코드·장애 확인
BACKGROUND_REGISTRATION장시간 작업 등록 실패D1·Worker·응답 ID 확인
USER_CANCELLED사용자 취소환불 표시 확인
PROCESSING_ERROR기타 처리 오류오류 ID로 서버 확인
실패한 일반 회원 요청은 쿠폰 환불로 표시되어야 한다. 실패인데 차감만 남으면 회원 잔액과 환불 로그를 함께 확인한다.

7. 개인정보 취급과 보관

관리 목적 확인 허용

  • 이메일·닉네임, 역할·상태, 가입·로그인 시각
  • 글쓰기 횟수와 실행 메타데이터
  • 관리자가 변경한 권한·건수 이력

수집·확인 금지

  • 검색 키워드·스토리·추가 요청
  • AI 완성 글과 뉴스·YouTube 본문·URL
  • API 키·OTP 원문·세션 토큰 원문
  • IP 주소·브라우저·기기 지문

내 원고함은 사용자가 명시적으로 저장한 콘텐츠로 일반 사용량 로그와 구분한다. 고객 지원 중 원고 확인이 필요하면 먼저 본인 동의와 대상 원고를 확인한다.

  • AI 실행 메타데이터는 400일 보관 후 자동 삭제한다.
  • 임의 삭제·장기 보존은 관리자 승인과 사유가 필요하다.
  • 계정 삭제 요청은 본인, 원고 범위, 법적 보존 필요 여부를 확인한다.
  • 운영 DB 전체를 대상으로 하는 삭제 명령을 사용하지 않는다.

8. 데이터 수집 정상 확인

  1. 메인 상단의 데이터 수집 완료 시각을 확인한다.
  2. 각 영역의 데이터 기준과 수집 주기를 확인한다.
  3. 목록이 비어 있으면 API 응답과 화면 표시를 분리해 점검한다.

9. 수집 장애 진단과 복구

  1. 운영 화면과 /api/data/status 마지막 시각을 비교한다.
  2. GitHub Actions 자동 실행 여부를 확인한다.
  3. 실행이 없으면 Scheduler Observability를 확인한다.
  4. unknown_cron이면 실제 Cron을 기준값과 비교한다.
  5. Actions 실패 시 실패 단계를 확인한다.
  6. Actions 성공 후 데이터가 그대로면 KV·R2 업로드와 바인딩을 확인한다.
  7. 긴급 복구는 GitHub Actions에서 워크플로를 수동 실행한다.

실시간: Crawl Portal Trends and Upload
시즌·문화: Crawl Daily Season and Culture Data

unknown_cron 복구

  1. Cloudflare → Workers & Pages → trafficcatcher-scheduler
  2. Settings → Trigger events → Cron triggers
  3. 잘못된 Trigger 삭제 후 기준 Cron 재등록
  4. 최대 15분 전파 대기
  5. Observability에서 새 이벤트 Cron 확인

10. 저장소별 점검

저장소용도이상 징후
D1 AUTH_DB회원·권한·사용량·감사로그인·관리 상세 실패
SQLite로컬 회원 기능로컬에서만 로그인·원고함 실패
Workers KV화면용 최신 JSON오래된 API 데이터
R2최신 원본 JSON·CSV복구 원본 누락
정적 JSONAPI 장애 폴백배포 시점 데이터만 표시

회원 DB와 트렌드 저장소는 서로 대체하지 않으며 장애 대응도 분리한다.

13. 현재 한계

  • 결제대행사·자동 갱신·플랜 만료일은 아직 구현되지 않았다.
  • premium 전환과 회수는 관리자 수동 작업이다.
  • 사용량은 AI 비용·품질 지표이며 법적 결제 원장을 대신하지 않는다.
  • 글자 수는 토큰 수나 실제 결제 금액과 동일하지 않다.
  • 원고함은 개인정보 최소화 사용량 로그와 별개의 콘텐츠 저장소다.
