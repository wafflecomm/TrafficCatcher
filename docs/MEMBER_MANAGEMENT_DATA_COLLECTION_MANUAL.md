# Traffic Catcher 회원 관리·데이터 수집 운영 매뉴얼

- 최종 갱신: 2026-08-29
- 대상: 최고 관리자, 운영 담당자, 장애 대응 담당자
- 목적: 회원 권한과 글쓰기 사용량을 안전하게 관리하고 수집 데이터의 정상 여부를 빠르게 확인·복구한다.

## 1. 운영 전 확인

### 로컬 환경

1. `실행_웹서버.bat`을 실행한다.
2. 회원 DB 파일과 `.env`가 존재하는지 확인한다.
3. 관리자 계정으로 로그인한다.
4. 관리자 페이지에서 회원 요약과 목록이 로딩되는지 확인한다.

### 운영 환경

1. `https://trafficcatcher.pages.dev/` 또는 연결된 운영 도메인에 접속한다.
2. 관리자 계정으로 이메일 OTP 로그인한다.
3. 내 프로필에서 관리자 페이지로 이동한다.
4. Cloudflare D1 `AUTH_DB`와 Worker가 연결돼 있어야 한다.

비밀키와 인증 토큰은 화면 캡처, 문서, 메신저, 장애 티켓에 붙여넣지 않는다.

## 2. 관리자 화면 구성

| 영역 | 확인·변경 내용 |
|---|---|
| 운영 요약 | 전체 회원, 등급, 이용 상태 등 집계 |
| 회원 목록 | 닉네임, 이메일, 가입·최근 로그인, 등급, 상태, 글쓰기 가능 건수 |
| 회원 상세 | 계정 정보, 사용량, 최근 글쓰기 실행, 관리자 변경 내역 |
| AI 실행 경로 | Cloudflare 직접 또는 한국 서버 중계 |
| 뉴스 검색 방식 | 네이버 뉴스·Google News와 보완 순서 |
| AI 모델 | 노출 모델과 기본 모델 |
| 역할별 권한 | 대시보드, 글쓰기, 개인화, 결제·쿠폰, 관리자 기능 |

회원 목록에서 한 행을 선택하면 상세 영역이 아코디언으로 펼쳐진다. 권한 버튼만 누르려는 경우에도 행이 열릴 수 있으므로 변경 전 대상 이메일과 닉네임을 다시 확인한다.

## 3. 회원 정보 확인 방법

### 계정 세부 정보

- 회원 ID: 내부 연결용 식별자
- 이메일: OTP 로그인 계정
- 닉네임: 화면 표시 이름
- 회원 등급: 일반, 유료, 운영자, 관리자
- 이용 상태: 정상 또는 이용 정지
- 가입일, 인증일, 최근 로그인, 최근 변경 시각

### 글쓰기 이용 현황

- 현재 가능: 일반 회원의 남은 글쓰기 건수
- 누적 지급: 관리자·추천 등으로 지급된 총 건수
- 누적 사용: 차감 후 환불을 반영한 기존 쿠폰 원장 수치
- 저장 원고: 내 원고함 저장 수
- 전체 글쓰기: 사용량 로그의 전체 실행 수
- 완료·실패: 결과 상태별 실행 수
- 이번 달 실행·사용량: 월간 운영 지표
- 누적 사용량: 무제한 회원을 포함한 총 실행 단위

`premium`, `operator`, `admin`은 현재 글쓰기가 무제한으로 표시되지만, 비용·품질 관리를 위해 실행 횟수는 계속 집계된다.

## 4. 회원 등급과 상태 변경

### 유료회원 등록

1. 회원 목록에서 이메일과 닉네임을 확인한다.
2. 회원 등급을 `유료 회원`으로 선택한다.
3. 이용 상태가 `정상`인지 확인한다.
4. `권한 저장`을 누른다.
5. 행을 다시 펼쳐 등급 변경과 관리자 변경 내역을 확인한다.

현재는 결제대행사 자동 연동 전이므로 결제 확인과 유료회원 지정은 운영자가 별도 승인 절차에 따라 수행한다. 종료일 자동 회수 기능은 아직 없으므로 만료 대상은 별도 운영 목록에서 확인해야 한다.

### 이용 정지

1. 신고·약관 위반·보안 사유와 근거를 내부 승인 절차로 확인한다.
2. 대상 계정의 이용 상태를 `이용 정지`로 변경한다.
3. 변경 사유를 운영 기록에 남긴다.
4. 복구 시 본인 확인 후 `정상`으로 되돌린다.

관리자 자신의 관리자 권한 또는 정상 상태는 화면에서 해제할 수 없다.

## 5. 글쓰기 가능 건수 관리

일반 회원만 잔여 건수를 직접 관리한다.

1. 회원 목록의 글쓰기 가능 건수를 확인한다.
2. 새 잔액을 입력한다.
3. 저장 버튼을 누른다.
4. 상세 화면의 현재 가능·누적 지급·누적 사용과 관리자 변경 내역을 확인한다.

건수 조정 시 결제 보상, 장애 보상, 프로모션, 운영 정정 중 하나로 사유를 구분해 내부 기록을 남기는 것을 권장한다. 유료·운영·관리자 등급은 무제한이므로 잔액보다 실제 사용량을 본다.

## 6. 최근 글쓰기 실행내역 읽는 법

각 실행에는 다음 정보만 표시된다.

- 새 글 작성 또는 글 보완
- 키워드·뉴스 또는 스토리·원고
- AI 모델과 실행 환경
- 자료 유형
- 입력·출력 글자 수
- 처리 시간과 사용량
- 쿠폰 차감 또는 환불
- 완료·실패·취소·시간 초과 상태
- 개인정보가 없는 오류 코드

### 대표 오류 코드

| 코드 | 의미 | 우선 조치 |
|---|---|---|
| `TIMEOUT` | 제한 시간 초과 | 모델·중계 서버·네트워크 확인 |
| `AI_CAPACITY` | AI 제공업체 혼잡 | 잠시 후 재시도, 모델 상태 확인 |
| `NETWORK` | 소켓·연결 오류 | 방화벽, DNS, 외부 연결 확인 |
| `AI_AUTH` | API 인증·권한 오류 | Secret 설정과 API 활성화 확인 |
| `CREDIT_REQUIRED` | 글쓰기 건수 부족 | 회원 잔액과 등급 확인 |
| `UPSTREAM_HTTP_*` | 외부 AI HTTP 오류 | 상태 코드와 제공업체 장애 확인 |
| `BACKGROUND_REGISTRATION` | 장시간 작업 등록 실패 | D1·Worker·응답 ID 확인 |
| `USER_CANCELLED` | 사용자가 작업 취소 | 환불 표시 확인 |
| `PROCESSING_ERROR` | 분류되지 않은 처리 오류 | 서버 로그의 오류 ID로 점검 |

실패한 일반 회원 요청은 `쿠폰 환불`로 표시되어야 한다. 실패인데 `쿠폰 차감`만 남으면 회원 잔액과 서버 환불 로그를 함께 확인한다.

### HTTP 524 또는 글쓰기가 오래 걸릴 때

HTTP 524는 AI 생성 실패 자체보다 Cloudflare가 동기 응답을 오래 기다려 연결을 종료한 경우에 발생할 수 있다. 현재 운영 서버의 모든 글쓰기 모델은 작업 ID를 먼저 받는 백그라운드 방식으로 처리한다.

```text
작업 등록: 최대 25초
상태 확인: 3초 간격
전체 완료 제한: 최대 5분
```

1. 회원 상세의 최근 글쓰기 실행내역에서 실행 환경이 `백그라운드`인지 확인한다.
2. 모델, 처리 시간, 상태, 오류 코드와 `provider_job_id` 연결 여부를 확인한다.
3. Cloudflare D1의 `ai_background_jobs`에서 같은 작업 ID의 상태가 `in_progress`, `completed`, `failed`, `cancelled` 중 무엇인지 확인한다.
4. 배포 직후 기존 화면을 사용 중이면 강력 새로고침한 뒤 다시 시도한다.
5. 5분을 넘긴 작업은 자동 취소 대상이며 일반 회원은 쿠폰 환불 여부를 확인한다.
6. 짧은 시간에 같은 버튼을 반복해서 누르지 않는다. 화면은 요청 즉시 버튼을 잠그고 진행 상태를 표시해야 한다.

백그라운드 방식은 524를 막지만 AI 모델의 실제 생성 시간을 줄이는 기능은 아니다. 긴 출력, 복잡한 시스템 지침, 삽화·쇼츠 동시 생성, 제공업체 혼잡 상황에서는 완료까지 수 분이 걸릴 수 있다.

## 7. 개인정보 취급 기준

### 관리자 화면에서 허용되는 확인

- 계정 식별을 위한 이메일과 닉네임
- 역할·상태·가입·로그인 시각
- 글쓰기 횟수와 실행 메타데이터
- 관리자가 변경한 권한·건수 이력

### 확인하거나 수집하지 않는 정보

- 사용자가 입력한 검색 키워드, 스토리, 추가 요청
- AI 완성 글과 뉴스·YouTube 본문·URL
- API 키, OTP 원문, 세션 토큰 원문
- IP 주소, 브라우저 정보, 기기 지문

내 원고함은 사용자가 명시적으로 저장한 콘텐츠이므로 일반 사용량 기록과 구분한다. 고객 문의 해결을 위해 원고 확인이 필요하더라도 먼저 본인의 동의와 정확한 대상 원고를 확인한다.

## 8. 사용내역 보관과 삭제

- AI 실행 메타데이터는 생성일로부터 400일 보관한다.
- 로컬 SQLite와 D1은 정상 DB 접근 시 만료 행을 자동 삭제한다.
- 만료 전 임의 삭제나 장기 보존이 필요한 경우 관리자 승인과 사유를 남긴다.
- 계정 삭제 요청은 본인 확인, 관련 원고 범위, 법적 보존 필요 여부를 검토한 뒤 처리한다.
- 삭제 전에는 대상 계정과 범위를 다시 확인하며 운영 DB 전체 삭제 명령을 사용하지 않는다.

## 9. 데이터 수집 정상 확인

### 화면 확인

1. 메인 상단의 `데이터 수집 완료` 시각을 확인한다.
2. 포털·방송·시즌·주식 영역의 데이터 기준과 수집 주기를 확인한다.
3. 최근 시각인데 목록이 비어 있으면 개별 API와 화면 렌더링을 분리해 점검한다.

### 운영 API 확인

```text
https://trafficcatcher.ai/api/data/status
https://trafficcatcher.ai/api/trends
https://trafficcatcher.ai/api/broadcast-top5
https://trafficcatcher.ai/api/season-events
https://trafficcatcher.ai/api/movie-releases
https://trafficcatcher.ai/api/performances
https://trafficcatcher.ai/api/netflix-top10
```

운영 도메인이 다른 경우 같은 경로를 실제 도메인에 적용한다.

### 정상 스케줄

| 수집 그룹 | Cloudflare Cron | 한국 시각 |
|---|---|---|
| 실시간 포털·방송 | `*/10 * * * *` | 24시간 매 10분 |
| 시즌·문화·OTT | `30 1,5,9,13,21 * * *` | 06:30부터 22:30까지 4시간 간격 |

## 10. 수집 장애 진단 순서

1. 운영 화면과 `/api/data/status`의 마지막 시각을 비교한다.
2. GitHub Actions에서 해당 워크플로의 자동 실행 여부를 확인한다.
3. 실행이 없으면 Cloudflare `trafficcatcher-scheduler` Observability를 확인한다.
4. `unknown_cron`이면 실제 Cron 값이 기준값과 일치하는지 확인한다.
5. 실행이 실패하면 GitHub Actions의 실패 단계를 확인한다.
6. Actions가 성공했는데 운영 데이터가 그대로면 KV·R2 업로드와 바인딩을 확인한다.
7. 긴급 복구는 GitHub Actions에서 해당 워크플로를 수동 실행한다.

### 워크플로 선택

- 실시간 포털·방송: `Crawl Portal Trends and Upload`
- 시즌·문화·OTT: `Crawl Daily Season and Culture Data`

### `unknown_cron` 복구

1. Cloudflare → Workers & Pages → `trafficcatcher-scheduler`
2. Settings → Trigger events → Cron triggers
3. 잘못된 Trigger 삭제
4. 기준 Cron을 정확히 다시 등록
5. 최대 15분 전파 대기
6. Observability에서 새 이벤트의 `controller.cron` 확인

## 11. 저장소별 점검

| 저장소 | 용도 | 이상 징후 |
|---|---|---|
| D1 `AUTH_DB` | 회원·권한·사용량·감사 | 로그인·관리자 상세 실패 |
| 로컬 SQLite | 로컬 회원 기능 | 로컬에서만 로그인·원고함 실패 |
| Workers KV | 화면용 최신 JSON | API가 오래된 데이터 반환 |
| R2 | 최신 원본 JSON·CSV | 복구용 원본 누락 |
| 정적 JSON | API 장애 폴백 | 배포 시점의 오래된 데이터만 표시 |

회원 DB와 트렌드 데이터 저장소는 서로 대체하지 않는다. KV/R2 장애가 회원 D1 삭제나 변경으로 이어지지 않도록 분리해서 대응한다.

## 12. 정기 운영 체크리스트

### 매일

- 데이터 수집 완료 시각과 주요 목록 확인
- GitHub Actions 최근 실시간·시즌 워크플로 성공 여부 확인
- AI 실패율과 환불 누락 여부 확인

### 매주

- 신규·정지·유료회원 변경 내역 검토
- 비정상적으로 많은 사용량 계정 확인
- 반복 오류 코드와 느린 모델 확인
- Scheduler `unknown_cron`·dispatch 실패 검색

### 매월

- 유료회원 목록과 별도 결제 승인 목록 대조
- 이번 달·누적 사용량과 AI 비용 비교
- 만료 예정 유료회원 수동 검토
- 관리자·운영자 계정 최소 권한 검토
- 백업과 복구 절차 표본 시험

## 14. 현재 한계와 주의사항

- 결제대행사, 자동 갱신, 유료 플랜 만료일은 아직 구현되지 않았다.
- `premium` 전환과 회수는 현재 관리자 수동 작업이다.
- 사용량은 AI 비용·품질 운영 지표이며 세금계산서나 법적 결제 원장을 대신하지 않는다.
- 입력·출력 글자 수는 토큰 수나 실제 결제 금액과 동일하지 않다.
- 원고함은 개인정보 최소화 사용량 로그와 별개의 사용자 콘텐츠 저장소다.
