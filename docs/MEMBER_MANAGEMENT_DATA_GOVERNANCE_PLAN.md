# Traffic Catcher 회원 관리·회원 정보·데이터 수집 기획서

- 최종 갱신: 2026-08-29
- 대상 환경: 로컬 Flask + SQLite, Cloudflare Worker + D1·KV·R2, GitHub Actions
- 문서 목적: 회원과 유료회원 운영, 개인정보 최소화, AI 사용량 기록, 서비스 데이터 수집을 하나의 관리 기준으로 확정한다.

## 1. 기획 목표

Traffic Catcher 시즌 2의 개인화·구독형 서비스 전환을 위해 다음 네 가지를 동시에 충족한다.

1. 이메일과 닉네임만으로 시작하는 최소 회원 체계
2. 등급·권한·글쓰기 가능 건수·실제 사용량을 근거로 한 유료회원 관리
3. 원문과 완성 글을 감시하지 않는 개인정보 최소화 사용 기록
4. 포털·방송·시즌·문화·주식 데이터를 안정적으로 수집하고 장애를 빠르게 복구하는 운영 체계

## 2. 운영 원칙

- **최소 수집**: 서비스 제공과 과금·장애 분석에 필요한 항목만 기록한다.
- **내용과 사용량 분리**: 사용자가 입력한 내용과 실행 메타데이터를 같은 기록에 저장하지 않는다.
- **명시적 저장**: 완성 글은 사용자가 `내 원고함`에 저장한 경우에만 원고 데이터로 취급한다.
- **역할과 기능 분리**: 회원 등급과 실제 기능 권한을 `role_feature_permissions`로 분리한다.
- **로컬·운영 동등성**: SQLite와 D1에서 같은 핵심 구조와 관리자 기능을 유지한다.
- **복구 가능성**: 최신 데이터, 원본 보관, 정적 폴백을 분리해 한 저장소 장애가 전체 서비스 중단으로 이어지지 않게 한다.
- **비밀정보 비기록**: API 키, OTP 원문, 세션 토큰 원문, 인증 헤더는 소스·문서·로그에 남기지 않는다.

## 3. 회원 등급과 기본 정책

| 등급 | 용도 | 글쓰기 정책 | 관리자 기능 |
|---|---|---|---|
| `member` | 일반 회원 | 보유 글쓰기 건수에서 1건씩 차감 | 없음 |
| `premium` | 유료 회원 | 현재 정책상 무제한, 사용량은 계속 집계 | 없음 |
| `operator` | 운영 담당자 | 무제한 | 회원 관리 가능, 권한 정책 변경 불가 |
| `admin` | 최고 관리자 | 무제한 | 회원·권한·서비스 설정 전체 관리 |

현재 구현은 결제대행사와 자동 갱신을 연결하지 않은 **관리자 지정형 유료회원** 단계다. 관리자가 회원 등급을 `premium`으로 변경하면 유료회원 정책이 적용된다. 결제일·만료일·환불 금액·영수증은 현재 회원 DB에 저장하지 않는다.

## 4. 회원 정보 데이터 구조

### 4.1 계정과 인증

| 데이터 | 목적 | 보호 기준 |
|---|---|---|
| 회원 ID | 내부 연결 키 | 외부 화면에서 불필요한 노출 금지 |
| 이메일 | OTP 로그인·계정 식별 | 관리자 외 전체 목록 노출 금지 |
| 닉네임 | 서비스 표시 이름 | 사용자가 변경 가능하도록 운영 |
| 역할·상태 | 기능 권한과 이용 정지 | 관리자 변경과 감사 기록 필요 |
| 인증·가입·최근 로그인 시각 | 계정 운영과 보안 확인 | 필요한 기간만 유지 |
| OTP 해시·세션 토큰 해시 | 인증 | 원문 저장 금지, 만료·폐기 적용 |

### 4.2 개인 설정

- AI 페르소나·톤앤매너와 개인 시스템 지침
- 화면 글꼴·크기·굵기·테마
- 네이버 블로그 글쓰기 열기 사용 여부
- 역할별 기능 권한

개인 설정은 회원 계정에 귀속되며 AI 사용내역과 분리한다. 관리자 화면에는 설정 내용 전체를 기본 노출하지 않는다.

### 4.3 내 원고함

`user_drafts`에는 사용자가 명시적으로 저장한 제목, Markdown 본문, 태그, 카테고리, 출처 URL이 저장된다. 이는 사용량 기록과 달리 콘텐츠 데이터이므로 다음 원칙을 적용한다.

- 회원 본인과 승인된 관리자 기능만 접근
- 계정별 최근 수정순 최대 5개 정책 유지
- 동일 제목 저장 시 갱신
- 삭제 요청 시 회원 식별과 범위를 확인한 뒤 처리
- 분석·광고·AI 학습 용도로 재사용하지 않음

## 5. 개인정보 최소화 AI 사용내역

### 5.1 기록하는 항목

`ai_writing_usage_logs`는 다음 메타데이터만 저장한다.

| 필드 | 의미 |
|---|---|
| `operation` | 새 글 작성 또는 글 보완 |
| `writing_mode` | 뉴스·키워드 또는 스토리·원고 |
| `model` | 사용한 AI 모델 식별자 |
| `status` | 진행 중, 완료, 실패, 취소, 시간 초과 등 |
| `execution_type` | 로컬, 클라우드 직접, 한국 서버 중계, 백그라운드 |
| `source_kind` | 키워드만, 뉴스, YouTube, 스토리, 글 보완 |
| `input_chars`, `output_chars` | 입력·출력 글자 수 |
| `duration_ms` | 처리 시간 |
| `usage_units` | 이용 횟수 집계 단위 |
| `credit_charged` | 글쓰기 건수 차감 여부 |
| `credit_refunded` | 실패·취소 후 복원 여부 |
| `error_code` | 개인정보가 제거된 오류 분류 코드 |
| `provider_job_id` | 백그라운드 작업 연결 ID |
| 생성·완료·갱신·보관 만료 시각 | 운영과 자동 삭제 기준 |

### 5.2 기록하지 않는 항목

- 검색 키워드와 기사 주제
- 사용자가 입력한 메모·스토리·추가 요청
- 뉴스·YouTube 제목, 본문, URL
- AI 시스템 지침과 페르소나 지침 내용
- AI가 생성한 완성 글
- API 키, OTP, 세션 토큰
- IP 주소, 브라우저 User-Agent, 기기 지문

### 5.3 보관 정책

- 실행 메타데이터 보관 기간: 생성일로부터 **400일**
- 로컬 SQLite와 Cloudflare D1 모두 정상 요청 시 만료 데이터를 자동 정리
- 기존 `ai_background_jobs`는 본문 없이 메타데이터로 한 번만 이관
- 법적 분쟁이나 보안 사고로 보존이 필요한 경우 별도의 승인·사유·종료일을 기록하는 절차를 추후 추가

### 5.4 운영 AI 요청의 HTTP 524 방지 구조

운영 서버에서는 모델 종류와 관계없이 모든 글쓰기 요청을 Gemini Interactions API의 백그라운드 방식으로 실행한다. 긴 본문, 시스템 지침, 뉴스 팩트, 삽화·쇼츠 4컷을 한 번에 생성하면 AI 처리 시간이 Cloudflare 연결 제한보다 길어질 수 있기 때문이다.

```text
글쓰기 요청
  → Worker가 로그인·권한·쿠폰 확인
  → background=true, store=true로 작업 등록
  → 25초 안에 작업 ID 수신
  → 브라우저가 3초 간격으로 상태 조회
  → 완료 결과 표시 또는 실패·취소·시간 초과 처리
```

- 작업 등록 연결은 25초로 제한해 Cloudflare가 장시간 원본 응답을 기다리지 않게 한다.
- 작업 ID는 `ai_background_jobs`와 `ai_writing_usage_logs.provider_job_id`에 로그인 회원 ID와 함께 연결한다.
- 작업 조회와 취소는 해당 회원의 세션으로만 허용한다.
- 브라우저와 Worker의 최대 대기 시간은 5분이며, 초과 시 작업 취소를 요청한다.
- 일반 회원의 실패·취소·시간 초과는 중복되지 않도록 한 번만 쿠폰을 환불한다.
- HTTP 524는 API 키나 입력 형식 오류가 아니라 Cloudflare가 동기 응답을 오래 기다린 연결 오류일 수 있다. 백그라운드 전환 후에도 실제 AI 생성 시간은 모델 혼잡과 출력량에 따라 길어질 수 있다.
- 입력 원문, 완성 글, 시스템 지침은 작업 관리 테이블과 사용량 로그에 저장하지 않는다.

## 6. 유료회원 관리 화면 기획

회원 목록의 한 행을 선택하면 아코디언 상세 영역에서 다음 정보를 확인한다.

- 계정: 닉네임, 이메일, 가입·인증·최근 로그인 시각, 역할, 상태
- 이용권: 현재 가능 건수, 누적 지급, 누적 사용
- 활동: 저장 원고 수, 전체·이번 달 실행 수, 완료·실패 수
- 비용 참고: 누적·이번 달 사용량, 모델, 실행 환경, 처리 시간
- 정산 참고: 쿠폰 차감과 환불 구분
- 운영 변경: 관리자 권한·상태·글쓰기 건수 변경 이력

관리자는 역할 변경, 이용 정지, 글쓰기 건수 등록·수정을 수행할 수 있다. 관리자 본인의 최고 권한 해제는 차단한다.

## 7. 서비스 데이터 수집 구조

```text
Cloudflare Cron Trigger
        ↓ workflow_dispatch
GitHub Actions
        ↓ Python 수집기
        ↓ 인증된 업로드
Workers KV ─ 화면용 최신 JSON
R2         ─ 최신 원본 JSON·CSV
        ↓
Worker 공개 API
        ↓ 장애 시
배포본 정적 JSON 폴백
```

### 7.1 데이터 그룹과 주기

| 그룹 | 주요 데이터 | 운영 수집 주기 | 로컬 수집 주기 |
|---|---|---|---|
| 실시간 | 포털 검색어, 통합 핫이슈, 인기 주식, 방송 편성·시청률 | 24시간 매 10분 | 실시간 데이터 10분 반복, 방송 데이터는 내부 TTL 적용 |
| 시즌·문화·OTT | 축제·행사, 영화, 공연, OTT, 시즌 후보 | 매일 06:30·10:30·14:30·18:30·22:30 | 장기 데이터는 내부 TTL로 불필요한 재수집 방지 |
| 뉴스·YouTube 팩트 | 선택 키워드의 글쓰기 참고 출처 | 콘텐츠 스튜디오 요청 시 | 콘텐츠 스튜디오 요청 시 |
| 네이버 검색어 트렌드 | 영역별 후보의 상대 검색지수 | 화면 접근과 캐시 정책에 따라 | 동일 기능, 서버 캐시 활용 |

운영 Cron 기준값은 `*/10 * * * *`, `30 1,5,9,13,21 * * *`이며 UTC로 등록한다.

### 7.2 저장 대상

- KV: `trends.json`, `broadcast_top5.json`, `season_events.json`, `movie_releases.json`, `performances.json`, `netflix_top10.json`
- R2: 위 최신 원본과 `realtime_trends.csv`, `signal_realtime_keywords.csv`
- D1: 회원·설정·사용량·감사 데이터
- SQLite: 로컬 개발 환경의 D1 대응 회원 데이터

회원 데이터와 트렌드 수집 데이터는 저장소와 접근 경로를 분리한다.

## 8. 권한·보안·감사 기준

- 관리자 API는 로그인 세션과 관리자 역할을 모두 확인한다.
- 상태·등급·글쓰기 건수·권한 변경은 `admin_audit_logs`에 변경 전후 값과 시각을 기록한다.
- Secret은 Cloudflare Secret, GitHub Actions Secret, 로컬 `.env`에서만 관리한다.
- 공개 데이터 API에는 회원 정보가 포함되지 않는다.
- 오류 로그는 인증값과 사용자 입력 원문을 출력하지 않는다.
- 운영자에게는 필요한 최소 관리자 기능만 부여하고 권한 정책 변경은 관리자만 수행한다.

## 9. 운영 지표와 경보 기준

| 지표 | 활용 |
|---|---|
| 월간 활성 회원·최근 로그인 | 서비스 이용 현황 |
| 전체·이번 달 글쓰기 사용량 | 플랜 설계와 비용 추정 |
| 완료율·실패율·오류 코드 | AI 품질과 장애 분석 |
| 평균·상위 처리 시간 | 모델과 중계 경로 성능 비교 |
| 쿠폰 차감·환불 비율 | 과금 신뢰성 점검 |
| 데이터 마지막 수집 시각 | 수집 중단 감지 |
| `unknown_cron`, dispatch 실패 | Scheduler 설정 장애 감지 |

권장 경보는 실시간 데이터가 정상 주기의 2배 이상 갱신되지 않거나, 특정 오류 코드가 짧은 시간에 반복될 때 발생시킨다.

## 10. 단계별 확장 계획

### 현재 단계

- 이메일 OTP 회원가입·로그인
- 역할·상태·기능 권한 관리
- 글쓰기 건수 등록·차감·환불
- 개인정보 최소화 사용내역과 관리자 상세 조회
- KV·R2 기반 수집 데이터 제공

### 다음 단계

1. `subscription_accounts`를 추가해 플랜, 시작일, 종료일, 자동 갱신 여부, 결제사 고객·구독 식별자의 해시 또는 비민감 참조값을 관리
2. 결제 웹훅의 서명 검증과 중복 처리 방지
3. 플랜 만료 시 `premium` 권한 자동 회수와 유예기간
4. 회원 본인의 사용량·보관 정책·동의 이력 조회
5. 관리자 CSV 내보내기는 개인정보 최소 열만 제공하고 권한·사유·만료 링크 적용
6. 400일 보관 데이터 자동 삭제 결과와 수집 지연 경보를 관리자 대시보드에 표시

결제 카드번호, 계좌번호, 주민등록번호는 Traffic Catcher가 직접 저장하지 않고 결제대행사의 토큰화 기능을 사용한다.

## 11. 완료 기준

- 로컬과 운영에서 같은 회원의 실행이 1회 단위로 집계된다.
- 성공 차감과 실패 환불이 관리자 화면에서 구분된다.
- 사용내역 테이블에 원문·완성 글·URL·API 키·IP 필드가 없다.
- 400일이 지난 사용내역이 자동 정리된다.
- 관리자 변경은 감사 로그로 확인할 수 있다.
- 데이터 상태 API와 운영 화면의 최종 수집 시각이 일치한다.
- Scheduler 장애 시 GitHub 수동 실행과 Cron 재등록으로 복구할 수 있다.
