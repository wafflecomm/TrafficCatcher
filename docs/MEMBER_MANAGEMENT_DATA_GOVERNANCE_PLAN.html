1. 기획 목표와 운영 원칙

  1. 이메일과 닉네임만으로 시작하는 최소 회원 체계를 운영한다.
  2. 등급·권한·글쓰기 가능 건수·실제 사용량으로 유료회원을 관리한다.
  3. 사용자의 원문과 완성 글을 감시하지 않는 사용 기록을 만든다.
  4. 포털·방송·시즌·문화·주식 데이터를 안정적으로 수집하고 빠르게 복구한다.
  • 최소 수집: 서비스 제공과 과금·장애 분석에 필요한 항목만 기록한다.
  • 내용과 사용량 분리: 사용자 콘텐츠와 실행 메타데이터를 같은 기록에 저장하지 않는다.
  • 명시적 저장: 완성 글은 사용자가 내 원고함에 저장한 경우에만 콘텐츠로 저장한다.
  • 역할과 기능 분리: 등급과 실제 기능 권한을 별도로 관리한다.
  • 로컬·운영 동등성: SQLite와 D1에서 같은 핵심 구조와 관리자 기능을 유지한다.
  • 비밀정보 비기록: API 키·OTP 원문·세션 토큰 원문·인증 헤더를 기록하지 않는다.

5. 유료회원 관리 화면

회원 행을 선택하면 다음 정보를 아코디언 상세 영역에서 확인한다.

  • 닉네임·이메일·가입·인증·최근 로그인·역할·상태
  • 현재 가능 건수·누적 지급·누적 사용
  • 저장 원고·전체 및 이번 달 실행·완료·실패
  • 모델·실행 환경·처리 시간·누적 및 월간 사용량
  • 쿠폰 차감·환불과 관리자 권한·건수 변경 이력

관리자는 역할, 이용 상태, 글쓰기 가능 건수를 변경할 수 있다. 관리자 자신의 최고 권한 해제는 차단한다.

7. 권한·보안·감사

  • 관리자 API는 로그인 세션과 역할을 모두 확인한다.
  • 상태·등급·건수·권한 변경은 변경 전후 값과 시각을 감사 기록에 남긴다.
  • Secret은 Cloudflare Secret, GitHub Actions Secret, 로컬 .env에서만 관리한다.
  • 공개 데이터 API에는 회원 정보를 넣지 않는다.
  • 오류 로그에는 인증값과 사용자 원문을 출력하지 않는다.
  • 운영자는 필요한 최소 기능만 사용하며 권한 정책은 관리자만 변경한다.

9. 단계별 확장 계획

현재 단계

  • 이메일 OTP 인증, 역할·상태·기능 권한
  • 글쓰기 건수 등록·차감·환불
  • 개인정보 최소화 사용내역과 관리자 상세 조회
  • KV·R2 기반 수집 데이터 제공

다음 단계

  1. 플랜·시작일·종료일·갱신 여부·비민감 결제 참조값을 저장하는 구독 계정 구조
  2. 결제 웹훅 서명 검증과 중복 방지
  3. 만료 시 유료 권한 자동 회수와 유예기간
  4. 회원 본인의 사용량·보관 정책·동의 이력 조회
  5. 개인정보 최소 열만 포함한 관리자 내보내기
  6. 자동 삭제 결과와 수집 지연 경보 표시

카드번호·계좌번호·주민등록번호는 직접 저장하지 않고 결제대행사의 토큰화를 사용한다.

10. 완료 기준

  • 로컬과 운영에서 같은 회원의 실행이 1회 단위로 집계된다.
  • 성공 차감과 실패 환불이 구분된다.
  • 사용내역에 원문·완성 글·URL·API 키·IP 필드가 없다.
  • 400일 경과 기록이 자동 정리된다.
  • 관리자 변경은 감사 기록으로 확인된다.
  • 데이터 상태 API와 화면의 수집 시각이 일치한다.
  • Scheduler 장애를 수동 실행과 Cron 재등록으로 복구할 수 있다.
