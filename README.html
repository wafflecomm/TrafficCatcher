📈 Traffic Catcher

실시간 이슈부터 방송·문화·OTT·시즌 키워드·인기 주식, AI 콘텐츠 제작까지

네이트, 다음, 줌, 시그널(Signal.bz)의 실시간 키워드와 인기 주식, 주간 방송 편성·시청률, 축제·행사, 개봉 영화, 공연, Netflix 주간 Top 10을 수집합니다. AI 콘텐츠 생성 API와 Google News RSS·네이버 뉴스 Search API·YouTube Data API v3를 연동해 블로그 글과 삽화·쇼츠 4컷을 생성합니다.

⚙️ 시스템 아키텍처 (Architecture)

본 시스템은 사용자의 인프라에 맞춰 두 가지 실행 방식을 유연하게 선택할 수 있도록 하이브리드 설계되었습니다.

1. 로컬 구동 모드 (Flask Web Server)

로컬 PC에서 python portal_crawler.py --web 명령으로 웹 서버를 띄워 실시간 수집을 컨트롤하고 확인합니다.

로컬 실행 ➔ Flask 웹 서버 구동 ➔ BeautifulSoup & API 크롤링 구동 ➔ CSV 누적 저장 ➔ 웹 대시보드 출력
2. 클라우드 서버리스 모드 (Cloudflare Cron & GitHub Actions)

로컬 컴퓨터를 꺼두어도 Cloudflare Cron Scheduler가 GitHub Actions를 호출합니다. GitHub Actions는 실시간 데이터를 새벽을 포함해 24시간 10분 간격으로, 시즌·문화·OTT 데이터를 매일 KST 06:30부터 22:30까지 4시간 간격으로 수집하고 최신 JSON은 KV, 원본 JSON·CSV는 R2에 저장합니다.

Cloudflare Cron ➔ GitHub workflow_dispatch ➔ portal_crawler.py 실행 ➔ KV·R2 업로드 ➔ Worker 데이터 API에서 즉시 조회

수집 키는 로컬 .env와 GitHub Actions Repository Secret에 저장합니다. AI 키는 Cloudflare Secret GEMINI_API_KEY와 로컬 서버 환경변수에서만 관리합니다. 로컬 콘텐츠 스튜디오에서는 AI·YouTube 키를 등록할 수 있지만 실제 값은 브라우저가 아닌 Git 제외 파일 .env에 저장됩니다. 키를 HTML·Python·JSON 또는 Git 커밋에 직접 기록하지 않습니다.

  • KOBIS: KOBIS_API_KEY — 개봉 영화 수집
  • KOPIS: KOPIS_API_KEY — 공연 수집
  • AI API 전용 키: 콘텐츠 생성 API를 활성화하고 이용 중인 AI 서비스에서 발급합니다.
  • YouTube 전용 키: Google Cloud에서 YouTube Data API v3를 활성화한 프로젝트에서 별도로 발급합니다.
  • 웹사이트 제한: trafficcatcher.pages.dev, 127.0.0.1, localhost를 실제 사용 환경에 맞춰 허용합니다.

운영 AI 모델·장시간 요청 처리

  • 운영 Worker는 AI Interactions API v1beta와 Api-Revision: 2026-05-20 헤더를 사용합니다.
  • gemini-3.7-flash, gemini-3.1-pro-preview는 백그라운드 작업으로 실행하고 /api/gemini/interactions/{id}에서 완료 상태를 조회합니다.
  • 작업 ID는 로그인 사용자와 연결해 D1 ai_background_jobs에 저장하며 실패한 일반 회원 작업의 쿠폰은 중복 없이 복원합니다.
  • 모델 과부하는 같은 모델로 최대 두 번 자동 재시도합니다. 빠른 작성이 필요하면 Flash 3.6 또는 Flash 3.5를 직접 선택할 수 있습니다.

✨ 글 보완하기

완성 글에서 빠진 정보나 수정할 사실을 입력하면 AI가 기존 글 전체와 요청을 함께 분석해 문맥에 자연스럽게 통합합니다. 뉴스·YouTube 검색은 반복하지 않고 기존 Fact Sources를 유지하며, 실패 시 원문을 보존합니다. 성공 후에는 수정 전으로 버튼으로 되돌릴 수 있습니다.

💰 시즌 황금 키워드 사용법

실시간 인기 검색 주식 영역 위에서 축제·행사, 개봉 영화, 공연, OTT 인기, 시즌 키워드, 명절·공휴일 탭을 선택합니다. 문화 일정은 기회지수와 30일 이내 시작일 기준으로 정렬됩니다. 각 후보 카드 전체를 선택하고 확인창에서 승인하면 선택한 이름으로 뉴스 검색이 시작됩니다.

기초 기회지수는 시즌 시점·상업 의도·4대 포털 신호만 반영하며 검색량이나 수익을 보장하지 않습니다. Google Trends와 광고 지표는 아직 연결 대기 상태로 화면에서 구분 표시됩니다.

👤 이메일 OTP 회원가입·로그인

이메일과 닉네임만 입력하고 6자리 OTP를 인증하면 최초 회원가입과 이후 로그인이 같은 흐름으로 처리됩니다.

  • 로컬: Flask + SQLite 회원 DB, SMTP 발송 또는 서버 실행 창 개발 OTP
  • 클라우드: Cloudflare Worker + D1 회원 DB + Resend 이메일 발송
  • 보안: OTP 5분 만료, 60초 재발송 제한, 5회 입력 제한, OTP·세션 토큰 해시 저장, HttpOnly 로그인 쿠키
  • 회원 인증 설정 안내
  • 관리자 시스템 지침 인증은 기존 비밀번호 방식을 유지하며 회원 권한 체계와의 통합은 다음 단계에서 진행합니다.

개인정보 최소화 사용내역과 유료회원 관리

  • 글쓰기·글 보완 실행 시 작업 종류, 키워드/스토리 모드, AI 모델, 성공/실패 상태, 실행 환경, 자료 유형, 입력·출력 글자 수, 처리 시간, 사용량, 쿠폰 차감·환불 여부, 안전한 오류 분류 코드, 실행 시각만 기록합니다.
  • 검색 키워드, 뉴스·YouTube 제목과 URL, 사용자가 입력한 스토리·요청문, 시스템 지침, AI 완성 글, API 키, IP 주소, 브라우저 정보는 사용내역 테이블에 저장하지 않습니다.
  • 사용내역은 생성 시점부터 400일간 보관한 뒤 로컬 SQLite와 Cloudflare D1에서 자동 삭제합니다. 기존 백그라운드 작업은 본문 없이 메타데이터로 한 번만 이관됩니다.
  • 관리자는 회원 행을 펼쳐 전체·이번 달 실행 횟수와 사용량, 성공·실패, 처리 시간, 모델·실행 환경, 쿠폰 차감 여부를 확인하고 회원별 글쓰기 가능 건수를 조정할 수 있습니다.
  • 프리미엄·운영자·관리자의 무제한 이용도 1회 단위로 집계해 비용과 품질을 확인할 수 있습니다.

🚀 사용 설명서 (Usage Guide)

다른 컴퓨터에서 이어서 작업하기

최신 운영 소스와 문서는 GitHub main 브랜치에서 받습니다.

git clone https://github.com/wafflecomm/TrafficCatcher.git
cd TrafficCatcher
git pull --ff-only origin main

기존 저장소에서는 작업 파일을 먼저 커밋하거나 별도로 보관한 뒤 git pull --ff-only origin main을 실행합니다. .env, .env.server.txt, SSH 개인키와 브라우저 저장 설정은 GitHub에 포함되지 않으므로 안전한 방법으로 별도 복사합니다. API 키는 Git 파일에 기록하지 않습니다.

네이버 블로그 글쓰기 연결

네이버 글쓰기 열기를 누르면 별도 도우미 프로그램 없이 현재 글의 HTML 서식을 복사하고 네이버 글쓰기 화면을 엽니다. 미완의 글서랍은 서비스 등급별 저장 한도 안에서 SQLite 또는 Cloudflare D1 AUTH_DB에 원고를 저장하며, 동일 제목은 기존 원고로 갱신합니다.

관리자가 저장 한도를 기존 저장 개수보다 낮춰도 원고·시스템 지침서·페르소나는 삭제되지 않습니다. 기존 항목의 조회·수정·적용·삭제는 유지되고 신규 저장과 복제만 차단됩니다.

네이버 계정 정보와 쿠키는 Traffic Catcher로 전송하지 않습니다. 스마트에디터에 원고를 붙여넣은 뒤 최종 발행 또는 예약 발행은 사용자가 직접 확인합니다.

방법 A. 로컬 대시보드 실행하기

1. 필요한 파이썬 라이브러리들을 설치합니다.

pip install flask requests beautifulsoup4 pandas lxml google-genai

2. 실행_웹서버.bat을 실행합니다. 기동 즉시 전체 데이터를 1회 수집한 뒤 로컬에서는 실시간 데이터를 10분 간격으로 자동 반복합니다.

실행_웹서버.bat

3. 인터넷 브라우저에서 http://127.0.0.1:5001로 접속합니다. 포트가 달라도 프로젝트당 웹 수집 서버는 하나만 허용되며, 중복 실행은 스케줄러 시작 전에 자동 종료됩니다.

방법 B. 클라우드 자동 수집 배포 (Cloudflare Cron, GitHub Actions & Pages)

1. 제공된 소스 코드 전체를 본인의 깃허브(GitHub) 저장소에 푸시(Push)합니다.

2. 깃허브 Actions 쓰기 권한 활성화 (중요): 저장소 Settings ➔ Actions ➔ General ➔ Workflow permissions에서 Read and write permissions를 선택하고 저장합니다.

3. Cloudflare 대시보드에 로그인하여 Workers & Pages ➔ Create application ➔ Pages ➔ Connect to Git 버튼을 통해 깃허브 저장소를 선택합니다.

4. 빌드 설정 화면에서 다음과 같이 세팅한 후 배포합니다.

  • Framework preset: None
  • Build command: (공란으로 비워둠)
  • Build output directory: . (마침표 하나 입력)

5. 별도 trafficcatcher-scheduler Worker에 GitHub Actions 실행 전용 최소 권한 토큰을 Secret으로 등록하고 배포합니다. Worker의 Cloudflare Cron Trigger가 실시간 수집은 24시간 10분 간격으로, 시즌·문화·OTT 수집은 매일 KST 06:30부터 22:30까지 4시간 간격으로 GitHub workflow_dispatch를 호출합니다. GitHub 워크플로에는 중복 schedule을 두지 않습니다. 자세한 설정은 Cron Scheduler 운영 가이드와 Cloudflare 데이터 저장소 전환 가이드를 참고합니다.

6. trafficcatcher-live-data KV와 trafficcatcher-data-archive R2 버킷을 만들고 운영 프로젝트에 각각 TRAFFIC_DATA_KV, TRAFFIC_DATA_ARCHIVE로 바인딩합니다. Cloudflare와 GitHub에 동일한 DATA_INGEST_TOKEN Secret을 등록한 뒤 초기 데이터를 업로드합니다. 설정 전에는 기존 GitHub 데이터 커밋 방식이 임시 폴백으로 유지됩니다.

포털 HTML과 내부 직렬화 데이터는 사이트 구조 변경의 영향을 받을 수 있습니다. 수집 실패 시 임의 기본값을 생성하지 않고 기존 정상 수집본을 유지하거나 오류 상태를 표시합니다. GitHub Actions가 생성한 최신 JSON은 Cloudflare KV, 원본 JSON·CSV는 R2에 저장하며 Pages 재배포 없이 Worker API로 제공합니다.

🛡️ 데이터 무결성 및 자동 복구

  • 단일 서버 실행: 포트가 달라도 프로젝트당 웹 수집 서버와 15분 스케줄러는 하나만 실행됩니다.
  • 스키마 버전 검증: 영화·공연·OTT JSON에 schema_version을 기록하고, 구버전 캐시는 최신이어도 다시 수집합니다.
  • 필수 필드 검사: 영화의 genre·nation, OTT의 title_ko가 누락된 캐시는 자동 복구합니다.
  • 안전한 저장: 고유 임시 파일을 완전히 기록한 뒤 원본과 원자적으로 교체해 동시 쓰기와 불완전한 JSON을 방지합니다.
  • 기본값 금지: 수집 실패 시 임의 데이터를 만들지 않고 검증된 기존 성공본만 유지합니다.

🧰 문제 해결

  • AI 로컬 엔진 전환: AI API 키, 콘텐츠 생성 API 활성화 및 선택 모델을 확인합니다.
  • WinError 10013: 중복 로컬 서버를 종료합니다. 로컬 AI 호출은 서버 환경변수 GEMINI_API_KEY를 사용합니다.
  • YouTube 로컬 검색 실패: YouTube 키의 웹사이트 제한에 127.0.0.1과 localhost를 추가합니다.
  • 로컬·Cloudflare 결과 차이: 시스템 지침, 모델, 각 도메인의 브라우저 저장 설정을 비교합니다.
  • 절대 규칙 미반영: 로컬 서버를 재시작하고 운영 지침 API 응답을 확인합니다. Cloudflare에서는 최신 운영 지침이 배포됐는지 확인합니다.
  • HTTP 524 또는 응답 지연: 강력 새로고침으로 최신 Worker를 사용하고 운영 빌드와 D1 ai_background_jobs 등록 여부를 확인합니다. 모든 모델은 작업 ID 등록 후 상태 조회 방식으로 처리되며, 모델 혼잡 시 완료까지 수 분이 걸릴 수 있습니다.
